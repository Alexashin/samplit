# Samplit

Библиотека сэмплов с интеллектуальным поиском и мульти-аутом. Программная часть ВКР Алексашина А.А. (ВГТУ, бИВТ-232, научрук — Пачевский Д.Е.). Команда из трёх человек (Артем, Кирилл Шевченко, Ваня Разинков), движок общий, у каждого своя оболочка. Артем ведёт проект, ребята работают по задачам.

Общаемся по-русски, неформально. Артем в C++ и JUCE не силён, ребята тоже: объяснять коротко и по делу, код писать самому.

## Что делаем

Плагин (VST3, AU, Standalone): указал папки → плагин индексирует сэмплы, ставит теги → поиск по описанию («драйвовый 808») и «похожие» → сэмплы на пэдах → каждый пэд на отдельный стерео-выход (мульти-аут) в DAW. Всё офлайн: на защите интернета нет.

- Стек: C++ / JUCE, CMake, SQLite, ONNX Runtime (для поиска по описанию).
- Платформы: Windows сейчас, macOS обязательно позже (Mac нет, вопрос с железом решим потом) — писать кроссплатформенно, без привязки к Windows.
- Тональность, нота, BPM и подобное — отдельная ветка допфункций (extras), не приоритет.

## Правила

- Аудиопоток: без аллокаций, блокировок и файлового ввода-вывода. Сэмплы грузятся в фоне и передаются в audio thread атомарной заменой.
- Ядро (`core/`) не зависит от JUCE GUI. Тяжёлое — в пул потоков.
- Мульти-аут: `BusesProperties` + `isBusesLayoutSupported`; пэд N → выход N по умолчанию, режим «всё в Main», если DAW не включила выходы.
- Работа без сети: ничего не качать при запуске, модели и база локально.
- Коммиты осмысленные, без упоминаний ИИ в коде, комментариях и истории. Комментарии в коде — по делу.
- Сэмплы в git не коммитить (`.gitignore`); тестовый набор лежит отдельно.
