# Samplit — инструкции Claude Code

## Контекст

Проект `Z:\repo\samplit`: C++/JUCE, VST3/Standalone (Windows сейчас; macOS/AU позже). Главная цель — **готовый мультимикрофонный барабанный инструмент Studio600**, а не прежний менеджер пэдов. Main стерео + 7 моно + 3 стерео выхода (переключатель «Стерео / Мульти-аут»), установка Setup из 12 мест (пресетов и миксов нет) и пакеты `.splpack`; Cubase 15 — основной целевой DAW. Поиск/SQLite/ONNX — вторая очередь.

Общайся **по-русски**, кратко и понятно человеку, который не обязан знать C++ и JUCE. Выполняй задачи автономно: разобраться → реализовать → проверить → исправить → отчитаться. Не останавливаться после плана, если запрошена реализация.

## Жёсткие технические инварианты

- Audio thread (`processBlock`): **никаких аллокаций, мьютексов, ожиданий, файлового/сетевого I/O или удаления тяжёлых объектов**. Проверять владение объектами, время жизни сэмплов и безопасный обмен состоянием между потоками.
- Загрузка, FLAC-декодирование, расшифровка и подготовка китов — в фоне, с отменой; в audio thread передаётся готовый объект безопасным способом. Не считать потокобезопасность доказанной без ревью/тестов.
- Микрофоны Studio600 моно; Main — стерео; в режиме «Мульти-аут» 7 моно-выходов (Kick In, Kick Out, Snare Top, Snare Bottom, Hat, Ride, Room Mid) и 3 стерео (Toms, Over, Room); неактивный в DAW выход отправляется в Main. Историческое отличие: до 11.11.2026 было 16 моно-выходов, ещё раньше (пэдовый вариант) 8 стерео.
- Один удар воспроизводит синхронно все его микрофоны. Для Studio600 velocity выбирает слой/удар, **не амплитуду** (если установка явно не задаёт иного).
- Источник точного маппинга — `.nki` / экспорт `tools/nki_extract.py` и `sample_library/mapping`; **нельзя** сопоставлять микрофоны по похожим числовым именам WAV: встречаются сдвиги нумерации. `docs/library-structure.md`.
- Звук Studio600 не меняется: **без обрезки хвостов, без int16, 24 бит как float32** (требование владельца библиотеки, 29.10.2026). Длинные WAV из папки («Моя библиотека…») играют со стримингом: в RAM голова клипа (~0,35 с), хвост читает поток `DiskStreamer` без блокировок. Пакеты `.splpack` v2 тоже стримятся: голова в RAM, хвост независимыми FLAC-кусками по 48000 кадров (`PackSource`, расшифровка и декодирование куска в потоке `DiskStreamer`); голов Studio600 ≈1,9 ГБ вместо ≈10 ГБ целиком (замер 12.11). Единственное ожидание в audio thread разрешено при офлайн-рендере (`isNonRealtime`, до 5 с на голос). `docs/streaming-design.md`.
- Офлайн-воспроизведение обязательно. Лицензию и пакеты проверять локально, сеть — только потенциальное фоновое продление, не блокирующее звук. Никогда не раскрывать `~/.samplit-license`, приватные ключи и токены.
- `core/` не зависит от JUCE GUI; сохранять переносимость Windows/macOS. Не коммитить аудиосэмплы, секреты, локальные сборки и дистрибутивы без явной необходимости.

## Рабочий процесс

1. Перед крупными правками — `git status`; не трогать чужие/посторонние изменения. Изучить узкий участок кода и только нужную спецификацию.
2. Для сложной задачи составить короткий план и **выполнить его**, а не просто перечислить шаги. Выбирать рациональные средства и субагентов: не запускать исследовательский fork/ревью для тривиальных задач.
3. После правок — соответствующие тесты, затем при необходимости полный `ctest`, `pluginval` и проверка хоста. Не выдавать отсутствие проверки за успешную проверку.
4. Для аудиопотока, конкурентной загрузки, лицензирования и криптографии проводить независимое ревью и анализ предельных случаев; при действительно сложной задаче предлагать переход на Opus, но не делать его условием работы.
5. Изменения архитектуры/контрактов фиксировать в соответствующем документе; завершённые задачи отражать в `docs/project-card.md`, контрольную точку — в `docs/current-status.md`. Не переписывать большие документы ради косметики.
6. Путь проекта нужен для текста ВКР: значимые решения, найденные ошибки (причина → исправление) и исследовательские выводы кратко фиксировать в `docs/decisions.md`; без фанатизма и дублирования `current-status.md`.
7. Не публиковать, не деплоить, не делать `git push`, не передавать файлы/лицензии третьим лицам и не совершать необратимые действия без разрешения. Осмысленные локальные коммиты — согласно задаче и настройкам пользователя. Не упоминать ИИ в коде/истории коммитов без причины.

## Полезные команды

```powershell
.\tools\build.ps1
.\tools\build.ps1 -Config Release
ctest --test-dir build\Debug --output-on-failure
```

Claude работает в Linux VM, поэтому Windows-сборку и тесты запускать самому через SSH (подробности и кодировка в глобальном `~/.claude/CLAUDE.md`):

```bash
ssh privelab-windows '[Console]::OutputEncoding=[Text.Encoding]::UTF8; cd Z:\repo\samplit; .\tools\build.ps1'
ssh privelab-windows '[Console]::OutputEncoding=[Text.Encoding]::UTF8; cd Z:\repo\samplit; ctest --test-dir build\Debug --output-on-failure'
```

Длинный вывод сборки/тестов фильтровать (`| Select-String`, `| Select-Object -Last 40`) или отдавать `log-analyst`.

Перед сборкой закрывать Reaper/Cubase/Samplit.exe, если они держат VST3. Дистрибутив и лицензии: только по `docs/delivery.md` и после проверки секретов. Учебные материалы ВКР находятся отдельно в `Z:\!CCHGEU\ВКР`; не переносить их в репозиторий без запроса.
