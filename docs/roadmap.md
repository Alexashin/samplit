## Дорожка P: редактор партии (по порядку, каждый шаг зависит от предыдущих)

### P1. `PatternPlayer`: проигрывание партии в audio thread — СДЕЛАНО 12.11 (`plugin/PatternPlayer.*`, `tests/pattern_player_tests.cpp`, слияние с MIDI в `processBlock`; Debug `ctest` 214/214; ревью без блокеров). В P2 вызывать `setPattern` только из message thread; `prepareToPlay` зовёт `setSampleRate` (в хостах это message thread)
- **Цель:** воспроизводить `Pattern` внутри плагина независимо от транспорта Cubase, с точностью до сэмпла.
- **Файлы:** новые `plugin/PatternPlayer.h/.cpp`, `tests/pattern_player_tests.cpp`; правки `plugin/PluginProcessor.{h,cpp}` (`processBlock`), CMake.
- **Инструкция:**
  1. Класс `PatternPlayer`. Снимок для audio thread: `struct Play { std::vector<PatternEvent> events; int64_t length; }` (создаётся в message thread из `Pattern::buildEvents (sampleRate)` и `lengthSamples`).
  2. Обмен как у `KitEngine`: `std::atomic<const Play*> current`, `std::atomic<const Play*> hazard`; audio thread в `beginBlock()` читает `current`, пишет `hazard`, перепроверяет `current` (цикл ограничен); `endBlock()` обнуляет hazard. Message thread: `setPattern (const Pattern&, double sampleRate)` создаёт новый `Play`, делает `current.store`, старый кладёт в `retired` (только message thread) и освобождает, когда `hazard != старый`.
  3. Транспорт плеера: `std::atomic<bool> playing, loop {true}`; методы `play()`, `stop()`. На audio thread своя позиция `int64_t pos` и номер прохода `pass`; фронт `playing` сбрасывает `pos = pass = 0`.
  4. Метод для блока: перебирает события, попадающие в `[pos, pos+n)`, с переходом через `length` при `loop` (внутри одного блока возможны два куска); при `loop == false` по концу ставит `playing = false`. Для каждого события отдаёт `(offsetInBlock, key, velocity, seedPos)`, где **`seedPos = pass * length + sample события`** (чтобы в петле записи не повторялись одинаково и результат оставался повторяемым).
  5. В `processBlock`: события партии объединять с MIDI-событиями блока по `offsetInBlock` (небольшой массив на стеке/в члене фиксированного размера, без аллокаций), перед каждым `noteOn` вызывать `kitEngine.setStrikePosition (seedPos, true)`; позицию экранных клавиш не трогать (`setStrikePosition (0, false)` уже есть). `prepareToPlay` пересоздаёт `Play` под новую частоту. Метроном в P1 не делаем.
  6. Ноты партии идут через тот же `kitEngine.noteOn`, поэтому choke, режимы групп и «Удар: плагин/партия» работают как у MIDI.
- **Тесты:** одинаковые события при разных размерах блока (7, 64, 100, 512); перенос через границу цикла внутри блока; остановка без цикла; `seedPos` растёт на `length` за проход; замена снимка из другого потока во время обработки (стресс, как у кита); два рендера одной партии через движок побитово равны.
- **Готово когда:** тесты и полный `ctest` зелёные, `code-reviewer` без блокеров.
- **Модель:** Opus на ТЗ-детали, реализация Sonnet; ревью обязательно.

### P3. Сила удара словами («палитра») — СДЕЛАНО 12.11 (`plugin/PatternPalette.*`: `buildPalette (kit, slot, meta*)`, `StrengthOption`; 3 теста, Debug `ctest` 221/221; скрытый `[.reallib-palette]` на настоящей библиотеке: палитра всех 12 мест не пуста, числа в окнах). - **Цель:** для места установки получить список ударов с понятными именами и точными числами velocity.
- **Файлы:** новые `plugin/PatternPalette.{h,cpp}`, `tests/pattern_palette_tests.cpp`.
- **Инструкция:** сначала выяснить, как имя и роль группы доходят до плагина: смотреть, откуда `plugin/InstrumentsPanel.cpp` берёт названия во вкладке «Группы ударов» (`pack::Group` из `PackCatalog`, `core/include/samplit/core/Manifest.h`), и использовать тот же источник. Функция `buildPalette (const Kit&, int slot)` возвращает `std::vector<StrengthOption> { key, groupId, name (русское), label (strong/medium/soft…), velocity, exact (bool), pairGroup/pairType }`:

  Эта же функция нужна для карты силы удара во вкладке «Инструменты» (T3).
- **Тесты:** на тестовом ките (`tests/kit_fixture.h`) и на настоящих манифестах Studio600 (`sample_library/packs-src`, скрытый тест `[.reallib*]` по образцу `real_library_tests.cpp`): у малого есть «Дроби» exact с несколькими числами и «Крещендо» с парой.
- **Готово когда:** палитра для Малого, Хэта, Бочки, Ride, томов не пуста и числа попадают в окна.
- **Модель:** Sonnet.
