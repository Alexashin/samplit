# Стартовый запрос для Claude Code

Работаем в существующем репозитории Samplit. Я передаю пакет с требованиями от Дениса Пачевского: главный документ `SAMPLIT_FEEDBACK_SPEC.md`, исходник `reference/pravki.docx`, извлечённые скриншоты в `reference/screenshots/`. Ориентируйся на существующие правила проекта `CLAUDE.md` / `AGENTS.md` и реальную архитектуру, ничего не выдумывай про исходный код.

**Цель:** внедрить правки безопасно и по этапам. Самое срочное — дать Денису возможность тестировать библиотеку: сэмплы определённых клавиш/velocity должны играть по MIDI Note On/Off, а команда на C-1 должна аккуратно глушить железо. Дополнительно есть неисправная клавиша Space для play/pause во встроенном редакторе. Остальные требования и активы описаны в ТЗ.

**Как работать:**

1. Сначала прочитай ТЗ полностью, сверь его с локальным репозиторием и составь **короткую карту кода**: где в действительности MIDI engine, воспроизведение voices, mixer/stereo outputs, sample map, state persistence, sequencer UI/key handling. Отметь несовпадения ТЗ с архитектурой.
2. Затем **сразу приступай к P0-1 и P0-2**, не ограничивайся планом. Меняй минимально необходимое, не проводи огромный рефакторинг. Учитывай VST3 noteId, note-off, velocity, sample offsets и real-time audio safety. Названия MIDI-нот из Cubase обязательно сопоставь с фактическими номерами в текущем проекте.
3. Добавь подходящие тесты, собери доступные таргеты и добейся контрольной точки **A**. Если Cubase невозможно запустить в среде, не говори, что тестировал в Cubase; дай чёткие действия ручной проверки.
4. После P0 продолжай P1/P2 по этапам ТЗ, с отдельными небольшими коммитами/логическими изменениями, **если среда, зависимости и время позволяют**. Главное — не ломать воспроизведение и не откладывать P0 ради косметики.
5. Два ZIP малого барабана и WAV SUB KICK доступны по ссылкам из ТЗ. Не перезаписывай старые WAV без анализа содержимого/совместимости. Если скачивание недоступно — прямо назови необходимые файлы.
6. Не переименовывай публичные выходы/состояние с потерей совместимости без объяснения миграции. Не удаляй данные, настройки и unrelated файлы, не создавай команды и агентов ради процесса.

**Отчёт после каждого этапа:** какие ID требований закрыты, конкретные изменённые файлы, проверка (тесты/сборка/ручной сценарий), оставшиеся риски, один следующий шаг. Не объявляй готовым то, что не проверено.

**Первый результат, который мне нужен:** рабочая P0-сборка для Дениса и короткий текст ему: что поменялось, какие MIDI-ноты и velocity проверить, что ожидается на Note Off и C-1.
