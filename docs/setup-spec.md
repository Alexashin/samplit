# ТЗ: установка из мест и паков, смысловая разметка групп

Составлено 11.11.2026 по правкам Пачевского (`pachevsky-feedback-plan.md`, пункты 1–4 этапа 1). Вкладка «Инструменты» (п. 5) и стерео-шины (п. 6) здесь описаны только там, где ядро должно их поддержать. Код на момент составления: `plugin/Kit.h`, `KitLoader.*`, `KitEngine.*`, `PluginProcessor.*`, `core/.../Manifest.h`.

## 1. Что меняется для пользователя

- Пресетов (китов и миксов) больше нет. Есть одна **установка**: фиксированные места Studio600 на своих клавишах.
- У каждого места: вкл/выкл, выбранный **пак** (звук) из установленных паков подходящего типа, громкость, режимы выбора ударов по группам.
- Установка хранится в проекте DAW. «Сделать стандартной» сохраняет её для новых экземпляров, «Сброс» возвращает стандартную.
- Замена пака на месте не прерывает звучание: старый кит играет, пока новый не готов.

## 3. Формат пака: что добавляется в манифест

Изменения аддитивные, `format` остаётся `1`; старые паки читаются (§3.4). Разбор — в `core` (`Manifest::Piece` получает поля `type`, `groups`; сейчас они попали бы в `extra`), проверки — в `verify`. Описать в `pack-format.md`.

### 3.1. Тип барабана

`pieces[].type`: `kick | snare | tom | hat | crash | china | splash | ride | other`. Пак подходит месту, если `type` совпадает. Один пак может содержать несколько барабанов (`studio600-toms` — четыре тома); тогда место выбирает пару «пак + барабан».

### 3.2. Группы (смысловая разметка)

Группа — то, что видит пользователь вместо сырых слоёв: «Дроби», «Крещендо», «Сбивки левой». Слой (`layers[]`) по-прежнему = клавиша + окно velocity, velocity-числа те же, что в Kontakt.

```json
"groups": [
  { "id": "center", "name": "Удары в центр", "hint": "Обычные удары, сила 75–127",
    "role": "main", "layers": ["k26_75_82", "k26_84_91", "k26_93_100"], "pick": "cycle" },
  { "id": "rolls", "name": "Дроби", "hint": "Каждое значение силы — свой записанный удар",
    "role": "roll", "layers": ["k26_51_73", "k27_51_73", "k28_51_73", "k29_51_73"],
    "pick": "exact", "picks": ["exact"] },
  { "id": "crescendo", "name": "Крещендо", "role": "crescendo", "layers": ["k32_42_73"],
    "pick": "exact", "picks": ["exact"], "pair": { "type": "tom", "group": "crescendo" } }
]
```

| поле | обяз. | смысл |
|---|---|---|
| `id` | да | уникален в барабане, латиница; ключ сохранения режима в проекте |
| `name` | да | человеческое имя по-русски (UI) |
| `hint` | нет | подсказка одной фразой |
| `role` | да | `main, ghost, rimshot, rimclick, fill, roll, crescendo, flam, choke, open, closed, half, pedal, closing, bell, edge, bow, other`; незнакомое значение читается как `other` без ошибки |
| `layers` | да | id слоёв; слой входит не более чем в одну группу (иначе ошибка `verify`) |
| `pick` | нет | режим по умолчанию: `random / cycle / exact` (по умолчанию `random`) |
| `picks` | нет | какие режимы пользователь может выбрать (по умолчанию все три); при одном значении переключатель не показывается |
| `pair` | нет | парная группа другого инструмента: `{ "type": <тип>, "group": <id группы> }` или `{ "place": <id места>, "group": ... }`. Смысл: одинаковые velocity-числа соответствуют друг другу (крещендо малого G#0 42–73 ↔ крещендо альтов 42–73). Движок не использует; это данные для будущего помощника (ВКР) |

«По кругу» и «Случайно» работают **внутри слоя**, то есть внутри окна velocity, — это и есть «группа velocity между пробелами» из заметки (движок уже так делает). Режим группы применяется ко всем её слоям.

### 3.3. Режим слоя

`layers[].pick` сейчас понимается только как `exact` (остальное → `random`, `KitLoader.cpp:592`). Исправить: читать `random / cycle / exact`. Приоритет: выбор пользователя для группы → `groups[].pick` → `layers[].pick` → `random`.

### 3.4. Старые паки (без `type` и `groups`)

- `type` выводится из id барабана по префиксу (`kick`, `snare*`, `tom*`, `hat`, `ride`, `crash*`, `china`, `splash`, иначе `other`).
- Без `groups` загрузчик строит по группе на каждый слой: `id` = id слоя, `name` = «<нота> <velLo>–<velHi>», `role` = `other`.

## 4. Клавиши пака на месте

Пак пишется под свои клавиши; место может иметь другие (Crash 16" на месте Crash 18", том на соседнем месте).

1. Все клавиши барабана лежат в клавишах выбранного места → без изменений.
2. Иначе, если все клавиши барабана лежат в клавишах другого места того же типа («родное» место) → ключ переносится по позиции: i-я клавиша родного места → i-я клавиша целевого.
3. Иначе (чужой пак): отсортированные клавиши барабана по порядку ложатся на клавиши места; лишние отбрасываются с предупреждением.

Перенос применяется к `Piece::keys`, `Layer::key`, `Hit::key` при сборке кита. Kick-паки после разделения (этап 2) уже лежат на 24, переносить нечего.

## 5. Установка (данные)

`plugin/Setup.h/.cpp`, без JUCE GUI:

```cpp
struct PlaceSetup {
    std::string placeId;
    bool enabled = true;
    std::string packId, pieceId;        // pieceId пуст: единственный барабан нужного типа в паке
    float levelDb = 0.0f;               // −60…+12
    std::map<std::string, Pick> picks;  // id группы → выбор пользователя (только отличия от умолчания)
};
struct Setup {
    std::vector<PlaceSetup> places;     // по всем kStudio600Places, в порядке slot
    static Setup factory();             // таблица §2
    juce::String toJson() const;
    static bool fromJson (const juce::String&, Setup&, juce::String& error);  // незнакомые места молча пропускает, недостающие берёт из factory()
};
```

JSON (один формат и для проекта, и для файла стандартной установки):

```json
{ "format": 1,
  "places": [ { "id": "snare", "enabled": true, "pack": "studio600-snare-live", "piece": "snare_live",
                "levelDb": 0.0, "picks": { "center": "random" } } ] }
```

- **Стандартная:** `<данные Samplit>/default-setup.json`. Новый экземпляр без состояния берёт её, при отсутствии или ошибке — `factory()`.
- «Сделать стандартной» пишет файл; «Сброс» загружает стандартную; в меню «Вернуть заводскую» удаляет файл и применяет `factory()`.
- Выбранный пак не установлен → место молчит, в карточке «Пак не найден: <id>», выбор **не стирается** (после установки пака звучит).

## 6. Каталог установленных паков

`PackCatalog` (message thread, скан в фоне при старте и по кнопке «Обновить»): список `{packId, title, pieces:[{id, type, name, groups}]}`.
- Режим «Моя библиотека…»: манифесты из `manifestDir` (как сейчас, с запасным `packs-src`).
- Режим пакетов (лицензия включена): `.splpack` с ключом; без лицензии пусто.
- Паки `studio600-unverified` и группы, целиком состоящие из `unverified`, в обычном режиме не показываются.

## 7. Сборка кита (загрузчик)

- Вход загрузчика вместо `Preset` — `KitSpec`: список `{slot, packId, pieceId, keyMap, picks}` по **включённым** местам + `includeUnverified`. `Setup` → `KitSpec` строится в message thread по каталогу.
- `Piece` получает `int slot` (место). `Layer::choice` указывает на `Kit::choices` = группы: id переключателя `<placeId>:<groupId>`, имя = имя группы. `Kit::kMaxChoices` поднять с 32 до 128 (сейчас у одного малого ~10 групп, у хэта больше).
- Выбор пользователя **запекается** в `Layer::pick` при сборке; `KitEngine::setKit` уже сбрасывает переключатели в «нет переопределения», поэтому между публикацией кита и `applyPicks` нет окна со старыми режимами.
- **Кэш клипов:** `KitLoadOptions::reuse` = текущий кит. Клипы с тем же источником (`packId+chunk+start+end` либо путь WAV + `start+end`) берутся из него без декодирования (`DecodedClip` неизменяем и разделяем; добавить поле `sourceKey`). Тогда смена пака на одном месте и вкл/выкл места не перечитывают остальную установку.
- Отмена и фон — как сейчас (`loadKitAsync`, `kitCancel`): новая правка отменяет незавершённую загрузку.

## 8. Процессор и движок

**Живые правки без перезагрузки кита:**
- Громкость места: `KitEngine::setPlaceLevel (slot, dB)` → `std::array<std::atomic<float>, kMaxPlaces = 16>`, индекс — `Piece::slot`, поэтому значение не зависит от смены кита (нет гонки «индексы старого кита»). Гейн берётся при старте удара (звучащий хвост не меняется; при необходимости позже — сглаживание по блокам).
- Режимы групп: как сейчас (`setPickChoice`).

**С перезагрузкой (через кэш, без декодирования):** вкл/выкл места, смена пака.

**Состояние проекта, `version` 3:** свойство `setup` = JSON §5; узлы `MIC` (микшер микрофонов) без изменений; `PRESET`/`mix`/`PICK` больше не пишутся. `getStateInformation` читает копию `Setup` под `stateLock` (хост зовёт из любого потока).

**Миграция `version` 2:** `factory()`; малый по `preset`: `studio600-ahead-low` → `snare-low`, `studio600-ambasador` → `snare-hi`, остальное → `snare-live`; узлы `MIC` переносятся; `PICK` и `mix` отбрасываются (id групп другие). Разводка выходов старых проектов Cubase теряется (решено, пользователей нет).

**Служебный режим:** переменная окружения `SAMPLIT_SERVICE=1` → `includeUnverified` и видимость `studio600-unverified` в каталоге. Без интерфейса-переключателя.

**Audio thread:** ничего нового, кроме чтения атомика громкости места при старте удара. Публикация кита, hazard pointer, вытеснение — без изменений. Ревью `code-reviewer` обязательно.

## 11. Тесты

- `Manifest`: разбор `type/groups/pair/picks`, незнакомая роль → `other`, слой в двух группах → ошибка `verify`, старый пак без полей.
- `Setup`: JSON туда-обратно, незнакомое место, недостающее место, битый JSON → `factory()`.
- Перенос клавиш §4: все три правила.
- Загрузчик: кит из `KitSpec`; выключенное место молчит; пак не найден → место молчит, остальные играют; кэш клипов (второй сбор не декодирует — счётчик декодов); приоритет режимов §3.3; `cycle` из манифеста.
