# Архитектура Samplit

**Схема на 29.10.2026, раздел об установке обновлён 11.11.2026**, сверена с кодом (версия 0.2.1). Если код и текст расходятся, верен код.

## Что строим

Samplit — инструмент для DAW (JUCE VST3/Standalone, AU запланирован) на библиотеке Studio600. Нажатие MIDI-клавиши инициирует **один удар**, для которого синхронно звучит набор моно-записей с разных микрофонов. Пользователь собирает установку из мест Studio600 (на каждом месте свой пак, вкл/выкл, громкость, режимы групп) и управляет уровнями и выходами микрофонов; экрана ручной сборки слоёв больше нет (удалён 28.10).

| Понятие | Значение |
|---|---|
| DAW | Cubase, Reaper и др. — хост музыкального инструмента |
| Main | Общий стерео-выход Samplit |
| Out 1–7 | Дополнительные **моно**-шины: Kick In, Kick Out, Snare Top, Snare Bottom, Hi-Hat, Ride, Room Mid |
| Out 8–10 | Дополнительные **стерео**-шины: Toms, Over, Room (микрофоны моно, разводятся панорамой) |
| Piece | Барабан/тарелка, занимает одну или несколько клавиш |
| Layer | Группа ударов по диапазону MIDI velocity |
| Hit | Конкретный удар с синхронными файлами нескольких микрофонов |
| Setup | Установка: 12 фиксированных мест Studio600 (`plugin/Setup.h`), у места пак своего типа, вкл/выкл, громкость, режимы групп. Пресетов и миксов нет (`setup-spec.md`) |
| `.splpack` | Сжатый и зашифрованный пакет с манифестом, аудио и идентификатором |

## Путь от MIDI до звука

```text
DAW MIDI note / velocity
        |
        v
Samplit processor / processBlock
        |
        v
Kit (из Setup): note -> piece -> velocity layer -> hit (`select.pick`)
        |
        +--> MIC 1 voice -----> Out N (mono) OR Main stereo
        +--> MIC 2 voice -----> Out M (mono) OR Main stereo
        +--> ...
        +--> MIC 15 voice ----> Out K (mono) OR Main stereo
```

- Удар и записи микрофонов выбираются **вместе** и запускаются синхронно. Поле `select.pick` управляет выбором внутри velocity-слоя; подробный контракт — в [`preset-format.md`](preset-format.md).
- Для исходной библиотеки Studio600 velocity — выбор слоя/удара, а не множитель громкости (`select.velocityToGain = 0`). Неназначенное значение velocity молчит; режимы случайного выбора и круга не переходят в соседний слой.
- Шины описываются через механизм JUCE `BusesProperties`/`isBusesLayoutSupported`: Main стерео, 7 моно и 3 стерео. Переключатель «Выходы: Стерео / Мульти-аут» (в проекте): «Стерео» шлёт всё в Main, «Мульти-аут» каждый микрофон на его выход. Невключённые DAW выходы сводятся в Main. Панорама действует на стерео-шинах и в Main, на моно-выходе её нет.
- Старые схемы с 8 пэдами и стерео-выходами **не описывают нынешний продукт**.

## Данные, модули и ответственность

| Часть | Задача |
|---|---|
| `plugin/PluginProcessor*`, `plugin/Kit*` | Приём MIDI, голосовой движок, микрофонный роутинг, состояние DAW |
| `plugin/Setup*`, `plugin/PackCatalog*` | `Setup`: данные установки и перенос клавиш пака на место. `PackCatalog`: скан установленных паков (типы, барабаны, группы), фоновый |
| `plugin/KitLoader*` | Фоновая загрузка, расшифровка, FLAC → float32 (24 бит без потерь) или WAV из папки, отмена и доставка готового кита |
| `plugin/DiskStreamer*` | Фоновое чтение хвостов длинных WAV с диска в кольцевые буферы по 32768 кадров. Ячейки (до 2048) и память колец (блоками по 64 ячейки, 8 МБ) выделяет поток стримера по мере надобности; audio thread только берёт и отпускает ячейки через атомики. Счётчики обрывов и ошибок чтения идут в «здоровье» (`getHealth`) и в строку статуса |
| `plugin/LicenseManager*` | Пути данных, манифесты, режим «Моя библиотека…»; проверка токена, ключи пакетов и продление работают только при `SAMPLIT_LICENSE=ON` (по умолчанию выключены) |
| `plugin/PluginEditor*`, `HeaderBar*`, `KeyboardView*`, `MixerPanel*`, `KitView*` | UI: шапка `HeaderBar` («Моя библиотека…», статус, «Сделать стандартной / Сброс / Вернуть заводскую»), меню места на схеме (пак, вкл/выкл, громкость, режимы групп), микшер, схема установки с выбором режима удара, строка статуса с предупреждениями о диске. Окно лицензии (`LicensePanel*`) создаётся только при `SAMPLIT_LICENSE=ON` |
| `core/src/Pack.cpp`, `core/src/Manifest.cpp`, `tools/packer/` | Контейнер `.splpack`, шифрование, packer/verify |
| `core/src/License*.cpp`, `tools/license_server/` | Подпись/валидация лицензии, выдача токенов |
| `tools/nki_extract.py`, `tools/mark_kit.py` | Извлечение маппинга `.nki` и разметка инструментов для упаковки |
| `core/` (индекс SQLite) | Старое/будущее ядро для поиска по личной коллекции; не обязательный путь звука в MVP |

Точные поля форматов определяют [`pack-format.md`](pack-format.md) (формат пресетов `preset-format.md` устарел); состав Studio600 — [`library-structure.md`](library-structure.md). Любое изменение сериализации требует проверки обратной совместимости уже установленных пакетов и проектов.

## Потоки и жёсткие ограничения

| Поток | Допустимая работа | Запрещённое в audio callback |
|---|---|---|
| Audio thread | Применение готовых MIDI/голосовых состояний, микширование в заранее подготовленные буферы | Дисковое/сетевое I/O, ожидание, мьютексы, аллокации, тяжёлое освобождение памяти |
| Фоновые workers | Чтение `.splpack`/WAV, дешифрование, декодирование FLAC, сборка нового кита; отдельный поток `DiskStreamer` дочитывает хвосты WAV | Нельзя менять активные буферы аудиопотока без безопасной передачи |
| UI/message thread | Правка установки, сборка `KitSpec`, обновление элементов интерфейса, управление параметрами | Не выполнять долгую загрузку синхронно |

**Критический контракт** — владение данными кита при замене (hazard pointer, `KitEngine::beginBlock/endBlock`). В начале каждого блока audio thread читает текущий кит, публикует его как «используемый» (`hazard`) и перепроверяет, что кит не сменился; в конце блока снимает защиту. Message thread удаляет списанный кит (`SamplitProcessor::collectGarbage`), только когда он не текущий, не помечен `hazard`, нет звучащих ударов этого кита (`strikeKit[]`) и ячеек стримера с ним. Это гарантия, а не пауза по времени. Тот же кит определяется по уникальному `serial`, а не по адресу. Параметры хоста из audio thread только ставят флаг (`paramsDirty`), применяет их таймер процессора (50 мс).

## Загрузка и память

1. Правка установки (смена пака, вкл/выкл места) в message thread: `Setup` → `PackCatalog` → `KitSpec` (список включённых мест с паком, барабаном, переносом клавиш и режимами).
2. Фоновый загрузчик проверяет наличие пакетов и лицензию, читает манифест, расшифровывает и декодирует файлы. В режиме **«Моя библиотека…»** пакеты и лицензия не нужны: WAV читаются прямо из выбранной папки по манифестам (`<данные>/manifests`, при их отсутствии — `packs-src` рядом с папкой библиотеки).
3. Звук **без потерь**: float32 (24 бит), без обрезки хвостов и без int16. Из пакетов `.splpack` клип целиком в RAM. Длинные WAV из папки: в RAM голова (~0,35 с), хвост стримится `DiskStreamer`; при офлайн-рендере (`isNonRealtime`) audio thread ждёт диск до 5 с на голос — единственное разрешённое ожидание.
4. `loadKit` берёт клипы текущего кита по `DecodedClip::sourceKey` (пак+блок+обрезка либо путь WAV+обрезка) без повторного декодирования (`KitLoadOptions::reuse`), поэтому смена пака на одном месте не перечитывает остальную установку. Новая правка отменяет незавершённую загрузку; у устаревшей загрузки `done` вызывается с `cancelled`.
5. Готовый кит публикуется в процессор без синхронной файловой работы во время звука. Режимы групп и микшер применяются **после** публикации (`setKit` сбрасывает переключатели), из актуального `Setup`, а не из снимка, по которому собирался кит.
6. Громкость места не требует перезагрузки: `KitEngine::setPlaceLevel(slot, dB)`, массив атомиков по `Piece::slot` (до 16 мест), значение берётся при старте удара.

Микрофоны: индекс фиксирован по слотам Studio600 (`kStudio600Mics` в `Studio600Names.h`: kick_in, kick_out, sn_top, sn_bot, hat, ride, tom_a1..a4, oh_1, oh_2, room_mid, room_1, room_2 = слоты 0..14); незнакомые id занимают слоты 15..23 (`Kit::kMaxMics` = 24), слот без микрофона в `Kit::mics` пустая заглушка. Микшер движка и `PluginProcessor::mixer` индексируются слотом и не зависят от состава кита. Параметры хоста: `mic_<id>_level` / `mic_<id>_pan` для 15 слотов (например `mic_kick_in_level`, «Kick In level»). Состояние проекта: версия 5 (формат как у 4, версия отмечает смену идентификаторов параметров; микшер и раньше хранился по id микрофона, поэтому v2–v4 мигрируют без потерь; автоматизация `micNN_*` из проектов до v5 не переносится), свойство `setup` (JSON установки), `multiOut` (режим «Стерео» / «Мульти-аут») и узлы `MIC` микшера. Выходы: Main стерео; в мульти-ауте 7 моно (Kick In, Kick Out, Snare Top, Snare Bottom, Hat, Ride, Room Mid) и 3 стерео (Toms, Over, Room), неактивные уходят в Main. Версия 3 читается как «Стерео»; `getStateInformation` читает копию `Setup` под `stateLock`. Версия 2 мигрирует: `factory()`, малый по прежнему пресету (`ahead-low` → `snare-low`, `ambasador` → `snare-hi`, иначе `snare-live`), `MIC` сохраняются, `PICK` и микс отбрасываются. Стандартная установка лежит в `default-setup.json` в данных Samplit. Служебный режим `SAMPLIT_SERVICE=1` показывает пак `studio600-unverified` и включает его удары.

Если ячейки стримера кончились, удар не теряет хвост: голос повторяет захват ячейки, а старейший удар с ячейками уходит в затухание 10 мс. Решение и измерения: [`streaming-design.md`](streaming-design.md).

## Обязательные проверки при изменении архитектуры

- Смена кита во время воспроизведения и отмена загрузки; отсутствие падений, щелчков и use-after-free.
- Изменение количества/активации mono buses в DAW и fallback в Main.
- Сохранение и восстановление установки/микшера (состояние v5, миграция v4, v3 и v2) при перезапуске проекта.
- Разные частоты дискретизации, размеры блока, полифония, mute/solo/choke.
- Отсутствие I/O/аллокаторов/блокировок в аудиопотоке; независимое ревью для конкурентных изменений.

Тестовые команды и DAW-сценарии: [`development.md`](development.md), [`daw/cubase.md`](daw/cubase.md).
