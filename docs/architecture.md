# Как устроен Samplit

Документ про то, что где лежит и как это работает. Он написан так, чтобы его можно было прочитать без опыта в музыкальном софте и в C++.

## Словарь

| Слово | Что это |
|---|---|
| DAW | Программа для записи музыки (Reaper, Cubase, FL Studio, Ableton). Хост, в который вставляется плагин |
| Плагин | Программа внутри DAW. Samplit это *инструмент*: получает ноты, отдаёт звук |
| VST3, AU | Форматы плагинов. VST3 работает на Windows и macOS, AU только на macOS (Logic) |
| Standalone | Тот же плагин как обычное приложение, без DAW |
| Пэд | Квадратная кнопка, которая играет один сэмпл. Как на драм-машинах |
| Сэмпл | Короткая звукозапись: удар бочки, снейр, хэт, бас |
| MIDI-нота | Команда «сыграй». У ноты есть номер (какая) и сила (velocity). Нота 36 играет пэд 1 |
| Шина (bus) | Группа каналов звука. Стерео-шина это два канала, левый и правый |
| Мульти-аут | Несколько выходов у одного плагина. Каждый пэд может уйти на свою дорожку DAW |
| Audio thread | Поток, в котором DAW просит у плагина звук. Он работает в реальном времени и не терпит задержек |
| JUCE | Библиотека на C++ для плагинов: окно, форматы VST3 и AU, работа со звуком |
| CMake | Программа, которая описывает, как собрать проект. Читает `CMakeLists.txt` |
| Submodule | Чужой репозиторий внутри нашего. Так подключён JUCE (`libs/JUCE`) |
| pluginval | Валидатор: проверяет, что плагин не падает и корректно общается с хостом |

## Путь звука

```
 DAW                          Samplit
 ┌────────────┐  MIDI-ноты   ┌─────────────────┐
 │ дорожка    │ ───────────► │ PluginProcessor │
 │ с плагином │              │  processBlock() │
 │            │              └───────┬─────────┘
 │ Main    ◄──┼───────────────┐      │ нота → номер пэда
 │ Out 1   ◄──┼─────────────┐ │      ▼
 │ Out 2   ◄──┼───────────┐ │ │  ┌───────────┐
 │ ...        │           │ │ │  │ PadEngine │ 8 голосов
 └────────────┘           │ │ │  └─────┬─────┘
                          └─┴─┴────────┘  звук пэда уходит на его шину
```

1. DAW много раз в секунду зовёт `processBlock`: «дай следующие 512 отсчётов звука» и передаёт MIDI-ноты за этот отрезок.
2. Процессор смотрит на ноты. Нота 36 это пэд 1, 37 пэд 2, и так до 43 (пэд 8). Остальные ноты игнорируются.
3. Движок пэдов (`PadEngine`) генерирует звук пэда.
4. Процессор кладёт звук в нужную шину. Если DAW включила отдельный выход пэда, звук идёт туда, иначе в Main.

Девятый голос движка отдан под прослушивание из браузера: он всегда играет в Main, чтобы прослушивание не попадало на дорожки пэдов.

## Файлы

### `plugin/` — сам плагин

| Файл | Что делает |
|---|---|
| `PluginProcessor.h/.cpp` | Главный класс `SamplitProcessor`. Объявляет 9 стерео-выходов, принимает MIDI, раскладывает пэды по шинам в `processBlock`. Здесь живёт «мозг» плагина |
| `Sample.h` | Загруженный в память сэмпл: звук, частота дискретизации, файл |
| `PadEngine.h/.cpp` | Движок: 8 голосов пэдов и голос прослушивания. Играет сэмпл с пересчётом частоты (файл 44,1 кГц на проекте 48 кГц звучит той же высоты), плавно глушит. Не знает про шины, только считает звук. Его легко тестировать |
| `SampleBrowser.h/.cpp` | Левая панель: выбор папки, фоновое сканирование, поиск по имени, список, волна выбранного файла. Стрелки и клик слушают, Enter кладёт на свободный пэд |
| `PadGrid.h/.cpp` | Сетка 4×2 пэдов: клик играет, перетаскивание из списка или проводника назначает, правый клик открывает меню (очистить, показать файл) |
| `PadSettings.h/.cpp` | Панель под пэдами: громкость (−24…+6 дБ), высота (±12 полутонов), панорама выбранного пэда. Двойной клик по ручке сбрасывает значение |
| `PluginEditor.h/.cpp` | Окно плагина: собирает логотип, браузер, пэды и панель настроек |
| `LookAndFeel.h`, `Brand.h` | Цвета и форма стандартных элементов JUCE по брендбуку |
| `CMakeLists.txt` | Описание плагина для сборки: форматы, название, коды, список файлов |

### `core/` — ядро без графики

| Файл | Что делает |
|---|---|
| `include/samplit/core/Library.h`, `src/Library.cpp` | Класс `Library`: индекс папки сэмплов в базе SQLite |
| `CMakeLists.txt` | Скачивает SQLite (amalgamation, версия и хеш зафиксированы), собирает библиотеку `samplit_core` |

`Library` хранит в таблице `samples` для каждого файла: путь, папку, имя, размер, время изменения, длительность, частоту дискретизации, число каналов и время добавления. Версия схемы лежит в таблице `meta`. База работает в режиме WAL, массовые записи идут одной транзакцией.

Сканирование (`scanFolder`) инкрементальное:

- новый файл (пути нет в базе) читается и добавляется;
- файл с тем же размером и временем изменения пропускается, сам звуковой файл при этом не открывается;
- если размер или время изменились, метаданные читаются заново и строка обновляется;
- строки, чьих файлов под этой папкой больше нет, удаляются (при отмене сканирования не удаляется ничего);
- нечитаемые файлы считаются ошибкой и в базу не попадают.

Поиск (`search`) требует, чтобы каждое слово запроса встретилось в имени или относительном пути, регистр не важен. Один объект `Library` это одно соединение с базой, из разных потоков его использовать нельзя: фоновому сканированию нужен свой экземпляр.

## Потоки и правила

В плагине работают три вида потоков, и это важно:

- **Audio thread.** Вызывает `processBlock`. Здесь нельзя выделять память, брать блокировки и читать файлы: любая задержка слышна как щелчок. Поэтому `PadEngine` держит голоса в массиве фиксированного размера, а общение с интерфейсом идёт через атомарные переменные (`std::atomic`).
- **Message thread.** Интерфейс и клики мыши. Клик по пэду не играет звук сам, он ставит флаг `pendingTriggers`, а audio thread подхватит его в начале следующего блока.
- **Фоновые потоки.** Сканирование папки (`SampleBrowser::Scanner`) и загрузка файлов (`loader` в процессоре). Готовый сэмпл передаётся в message thread, а оттуда в движок через атомарный указатель.

### Как сэмпл попадает в аудиопоток и не удаляется раньше времени

1. Фоновый поток читает файл в `Sample` (`readSample`).
2. В message thread процессор держит `shared_ptr` на сэмпл (`owned`) и передаёт движку голый указатель (`setSample`, атомарно).
3. Аудиопоток при ноте берёт этот указатель и играет. Он никогда ничего не выделяет и не удаляет.
4. Если сэмпл на пэде заменили, старый уходит в список `retired`. Таймер раз в секунду удаляет его, только когда движок подтверждает, что сэмпл уже не звучит (`isUsing`).

Примеры в коде:
- `triggerPad` (UI → audio): `pendingTriggers.fetch_or(1u << pad)`.
- `getActiveMask` (audio → UI): процессор пишет, какие пэды звучат, интерфейс читает 30 раз в секунду и перерисовывается.

## Как включается мульти-аут

В конструкторе `SamplitProcessor` объявлены шины: Main (включена) и `Out 1`…`Out 8` (выключены). DAW сама решает, включать ли выключенные. В Reaper это происходит при настройке роутинга дорожки (см. `docs/daw/reaper.md`).

`isBusesLayoutSupported` говорит DAW, какие раскладки допустимы: все шины стерео, Main обязателен.

Дальше `processBlock` для каждого пэда проверяет, включена ли его шина (`getBus(false, pad + 1)->isEnabled()`). Если да, пишет звук в неё и ставит бит в `separateOutMask` (интерфейс покажет `OUT N`). Если нет, звук идёт в Main.

## Что дальше

Индекс папок в `core/` уже есть, но плагин его пока не использует. Дальше в ядре появятся анализ звука, теги и поиск по описанию, а браузер будет брать список не прямым обходом папки, а из индекса.
