# Архитектура Samplit

**Актуальная схема на 29.10.2026**, сверена с кодом (версия 0.2.1). Если код и текст расходятся, верен код.

## Что строим

Samplit — инструмент для DAW (JUCE VST3/Standalone, AU запланирован) на библиотеке Studio600. Нажатие MIDI-клавиши инициирует **один удар**, для которого синхронно звучит набор моно-записей с разных микрофонов. Пользователь выбирает готовый пресет и управляет уровнями и выходами микрофонов; экрана ручной сборки слоёв больше нет (удалён 28.10).

| Понятие | Значение |
|---|---|
| DAW | Cubase, Reaper и др. — хост музыкального инструмента |
| Main | Общий стерео-выход Samplit |
| Out 1–16 | Дополнительные **моно**-шины, которые хост может активировать |
| Piece | Барабан/тарелка, занимает одну или несколько клавиш |
| Layer | Группа ударов по диапазону MIDI velocity |
| Hit | Конкретный удар с синхронными файлами нескольких микрофонов |
| Preset | Набор пакетов, инструментов, правил выбора ударов, уровней и выходов |
| `.splpack` | Сжатый и зашифрованный пакет с манифестом, аудио и идентификатором |

## Путь от MIDI до звука

```text
DAW MIDI note / velocity
        |
        v
Samplit processor / processBlock
        |
        v
Preset + Kit: note -> piece -> velocity layer -> hit (`select.pick`)
        |
        +--> MIC 1 voice -----> Out N (mono) OR Main stereo
        +--> MIC 2 voice -----> Out M (mono) OR Main stereo
        +--> ...
        +--> MIC 15 voice ----> Out K (mono) OR Main stereo
```

- Удар и записи микрофонов выбираются **вместе** и запускаются синхронно. Поле `select.pick` управляет выбором внутри velocity-слоя; подробный контракт — в [`preset-format.md`](preset-format.md).
- Для исходной библиотеки Studio600 velocity — выбор слоя/удара, а не множитель громкости (`select.velocityToGain = 0`).
- Шины описываются через механизм JUCE `BusesProperties`/`isBusesLayoutSupported`: Main стерео, до 16 моно. Невключённые DAW выходы сводятся в Main. Панорама относится к стерео-миксу Main; поведение в отдельных каналах должно соответствовать текущей реализации.
- Старые схемы с 8 пэдами и стерео-выходами **не описывают нынешний продукт**.

## Данные, модули и ответственность

| Часть | Задача |
|---|---|
| `plugin/PluginProcessor*`, `plugin/Kit*` | Приём MIDI, голосовой движок, микрофонный роутинг, состояние DAW |
| `plugin/KitLoader*` | Фоновая загрузка, расшифровка, FLAC → float32 (24 бит без потерь) или WAV из папки, отмена и доставка готового кита |
| `plugin/DiskStreamer*` | Фоновое чтение хвостов длинных WAV с диска в кольцевые буферы (1024 ячейки), без блокировок со стороны audio thread |
| `plugin/LicenseManager*` | Локальная проверка токена, извлечение ключей пакетов, потенциальное фоновое продление; пути данных, манифесты, режим «Моя библиотека…» |
| `plugin/PluginEditor*` (шапка: кит, микс, лицензия; вкладки), `KeyboardView*`, `PresetPanel*`, `MixerPanel*`, `KitView*`, `LicensePanel*` | UI: пресеты (список, «Сохранить как…», папки пресетов и пакетов, «Добавить пакет…», «Моя библиотека…»), микшер, схема установки с выбором режима удара; окно лицензии скрыто (`kLicenseUi = false`) |
| `core/src/Pack.cpp`, `core/src/Manifest.cpp`, `tools/packer/` | Контейнер `.splpack`, шифрование, packer/verify |
| `core/src/License*.cpp`, `tools/license_server/` | Подпись/валидация лицензии, выдача токенов |
| `tools/nki_extract.py`, `tools/mark_kit.py` | Извлечение маппинга `.nki` и разметка инструментов для упаковки |
| `core/` (индекс SQLite) | Старое/будущее ядро для поиска по личной коллекции; не обязательный путь звука в MVP |

Точные поля форматов определяют [`pack-format.md`](pack-format.md) и [`preset-format.md`](preset-format.md); состав Studio600 — [`library-structure.md`](library-structure.md). Любое изменение сериализации требует проверки обратной совместимости уже установленных пакетов и пресетов.

## Потоки и жёсткие ограничения

| Поток | Допустимая работа | Запрещённое в audio callback |
|---|---|---|
| Audio thread | Применение готовых MIDI/голосовых состояний, микширование в заранее подготовленные буферы | Дисковое/сетевое I/O, ожидание, мьютексы, аллокации, тяжёлое освобождение памяти |
| Фоновые workers | Чтение `.splpack`/WAV, дешифрование, декодирование FLAC, сборка нового кита; отдельный поток `DiskStreamer` дочитывает хвосты WAV | Нельзя менять активные буферы аудиопотока без безопасной передачи |
| UI/message thread | Выбор пресета, обновление элементов интерфейса, управление параметрами | Не выполнять долгую загрузку синхронно |

**Критический контракт** — владение данными кита при замене. Новый кит должен попадать в audio thread безопасно; старый не удаляется, пока возможно чтение/активные голоса. Конкретный механизм атомарного обмена и освобождения **нужно подтвердить кодом и стресс-тестами**: исходные файлы не входят в комплект.

## Загрузка и память

1. Пользователь выбирает пресет; список пакетов берётся из его JSON.
2. Фоновый загрузчик проверяет наличие пакетов и лицензию, читает манифест, расшифровывает и декодирует файлы. В режиме **«Моя библиотека…»** пакеты и лицензия не нужны: WAV читаются прямо из выбранной папки по манифестам (`<данные>/manifests`, при их отсутствии — `packs-src` рядом с папкой библиотеки).
3. Звук **без потерь**: float32 (24 бит), без обрезки хвостов и без int16. Из пакетов `.splpack` клип целиком в RAM. Длинные WAV из папки: в RAM голова (~0,35 с), хвост стримится `DiskStreamer`; при офлайн-рендере (`isNonRealtime`) audio thread ждёт диск до 5 с на голос — единственное разрешённое ожидание.
4. Подготовленный кит передаётся в процессор без синхронной файловой работы во время звука.

Решение и измерения: [`streaming-design.md`](streaming-design.md). При ограничениях RAM решение пересматривается только после измерений на целевых ПК.

## Обязательные проверки при изменении архитектуры

- Смена кита во время воспроизведения и отмена загрузки; отсутствие падений, щелчков и use-after-free.
- Изменение количества/активации mono buses в DAW и fallback в Main.
- Сохранение и восстановление пресета/микшера при перезапуске проекта.
- Разные частоты дискретизации, размеры блока, полифония, mute/solo/choke.
- Отсутствие I/O/аллокаторов/блокировок в аудиопотоке; независимое ревью для конкурентных изменений.

Тестовые команды и DAW-сценарии: [`development.md`](development.md), [`daw/cubase.md`](daw/cubase.md).
