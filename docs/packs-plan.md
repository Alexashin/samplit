# План: пакеты с библиотекой Пачевского, пресеты, лицензия

Статус: план, код ещё не написан. Основа: текущая модель «группа → зоны» (`plugin/Instrument.h`) переделывается под мульти-микрофонные барабаны.

## 1. Что строим

Готовый инструмент. Пользователь выбирает пресет, играет по клавишам, в DAW получает микс на Main и по желанию каждый микрофон на своём выходе. Маппинг и сэмплы лежат в зашифрованных сжатых пакетах, которые привязаны к лицензии.

Термины:

| Слово | Что это |
|---|---|
| Микрофон (mic) | Канал записи: Kick In, Snare Top, Overhead L и т. д. Имеет имя и выход по умолчанию |
| Барабан (piece) | Кик, малый, том 1, хэт. Сидит на одной клавише (или нескольких) |
| Удар (hit) | Одна вариация звучания барабана: «по корпусу», «сильно», «две палочки», «кривой». Диапазон velocity и **набор файлов по микрофонам** |
| Пакет (pack) | Файл `.splpack`: манифест + аудио, сжатый и зашифрованный |
| Пресет | Список барабанов, пакетов, уровней микрофонов, выходов |
| Токен лицензии | Подписанный файл со сроком действия и ключами пакетов |

Ключевое правило движка: **вариация выбирается один раз на удар**, и играют все микрофоны этого удара вместе. Иначе фаза и характер между микрофонами разъедутся. Сейчас каждая группа выбирает сама, это придётся заменить.

## 2. Данные

### Манифест пакета (JSON внутри контейнера)

```json
{
  "id": "pach-base", "version": 1, "tier": "base",
  "requires": [],
  "mics": [
    { "id": "kick_in", "name": "Kick In", "role": "close", "out": 1 },
    { "id": "oh_l",    "name": "Overhead L", "role": "overhead", "out": 5 }
  ],
  "pieces": [
    { "id": "snare", "name": "Малый", "keys": [38], "choke": null,
      "hits": [
        { "id": "snare_rim_01", "artic": "rim", "velLo": 1, "velHi": 40,
          "files": { "snare_top": "chunk:114", "snare_bot": "chunk:115", "oh_l": "chunk:116" } }
      ] }
  ]
}
```

- `files` ссылается на блок аудио в контейнере.
- Пакеты складываются: `mid` добавляет к тем же барабанам новые удары и микрофоны (сливаются по `piece.id` и `hit.id`). Отдельный пакет «тарелки» добавляет новые барабаны на свои клавиши.
- Пресет хранится отдельным JSON (не шифруется, ключей не содержит): какие пакеты нужны, уровни и выходы микрофонов, кривая «Живой» режима.

### Контейнер `.splpack`

```
[заголовок: magic, версия формата, id пакета, длина манифеста]
[манифест: зашифрован]
[таблица блоков: смещения, длины, nonce]
[блок 0: FLAC файла, зашифрован] [блок 1] ...
```

- Аудио: FLAC без потерь (в JUCE уже есть). Сжатие примерно вдвое от WAV.
- Шифрование: XChaCha20-Poly1305 (библиотека Monocypher, один файл, подтягиваем как SQLite). Каждый блок шифруется отдельно, чтобы читать любой файл без распаковки всего пакета, плюс проверка целостности.
- Ключ пакета случайный, 32 байта. Лежит не в пакете, а в токене лицензии (п. 5).
- Один пакет = один файл, пакеты кладутся в папку `Samplit/Packs` в профиле пользователя. Плагин её сканирует при запуске. Скачивать пакеты плагин не умеет, раздаём отдельно.

Один код формата (`core/pack`, без JUCE) используют и плагин, и утилита сборки. Так нельзя рассинхронизировать запись и чтение.

## 3. Разметка и сборка (то, что делаем сами)

1. **Скан.** Скрипт `tools/scan_library.py` обходит папку библиотеки и по правилам из `tools/rules.json` (регулярки по именам файлов и папок) выделяет: барабан, микрофон, артикуляцию, слой velocity, номер вариации. Результат: черновой `mapping.json` + отчёт «не распознано».
2. **Правка.** Правим `mapping.json` руками. Для первых «примерочных» пакетов этого достаточно. Потом с Пачевским корректируем реальный маппинг.
3. **Сборка.** `samplit-packer build mapping.json --out pach-base.splpack` (C++ консольная утилита на `core/pack`): конвертирует в FLAC, шифрует, пишет контейнер и манифест.
4. **Проверка.** `samplit-packer verify`: целостность, все ли файлы на месте, нет ли удара без микрофона, дыр по velocity.

Распознавание имён зависит от реальных файлов, поэтому правила пишем после того, как увидим список файлов.

## 4. Движок

Новая модель вместо `Group/Zone`:

```
Kit { mics[], pieces[] }
Piece { keys[], hits[], chokeGroup }
Hit { velLo, velHi, artic, files[micIndex] -> Sample* }
```

`noteOn(note, velocity)`:
1. Найти барабан по клавише.
2. Выбрать удар: среди ударов, чей диапазон velocity содержит velocity, случайно, без повтора предыдущего.
3. **Режим «Живой»:** velocity задаёт центр, а удар берётся случайно из соседних по диапазону (±N, ширина в пресете). Так один и тот же velocity не даёт один и тот же файл.
4. Для каждого микрофона удара запустить голос на выход этого микрофона (с запасом по уровню и панораме из пресета). Все голоса одного удара стартуют в одном сэмпле.
5. Choke: хэт и подобное, барабан в `chokeGroup` глушит голоса других барабанов из той же группы (быстрый фейд, как сейчас у `stop`).

Остаётся как есть: выход микрофона не включён в DAW → микрофон играет в Main. 16 стерео-выходов достаточно: десять микрофонов плюс запас. Main получает микс всех микрофонов.

Текущий редактор групп/зон превращается в служебный режим для нас (разметка и отладка маппинга на слух). Включается флагом, в релизе скрыт.

## 5. Память и загрузка

Грубая оценка: 10 микрофонов × 50 ударов × 15 барабанов × ~1,5 с при 48 кГц, моно, float32 ≈ 2 ГБ. Поэтому:

- Загружать **только то, что нужно пресету**, фоновыми потоками (расшифровка + декодирование FLAC), с индикатором прогресса. Играть можно, пока докачивается.
- Хранить в RAM как **int16** (преобразование в float при воспроизведении) и обрезать тихие хвосты. Ориентир: вдвое меньше памяти.
- Если не хватит: предзагружать только начало удара, хвост стримить с диска (потом, при необходимости).
- Сначала смотрим реальный объём библиотеки и решаем.

## 6. Лицензия (сервер, срок, продление)

Это меняет правило проекта «всё офлайн». Новое правило: **плагин работает офлайн по подписанному токену, сеть нужна только чтобы получить и продлить токен**. Ничего не качается при запуске и не блокирует звук.

- **Токен** (JSON, подпись Ed25519): id лицензии, пользователь, отпечаток машины, список пакетов с их ключами, `notBefore`, `expires`. Срок 7 или 30 дней, задаётся на сервере по лицензии. Публичный ключ зашит в плагине, приватный только на сервере.
- **Привязка к машине:** ключи пакетов в токене зашифрованы ключом, выведенным из отпечатка машины (на macOS и Windows считается по-разному). Токен, скопированный на другой компьютер, не откроет пакеты.
- **Продление:** на старте и раз в сутки в фоновом потоке плагин пробует обновить токен. Не вышло — продолжает на старом до `expires`. Не продлили — пакеты закрываются (играет только демо), сэмплы остаются зашифрованными.
- **Защита от перевода часов:** плагин хранит последнее увиденное время и не принимает меньшее.
- **Для защиты диплома (без интернета):** выпускаем токен на длинный срок заранее, на тот же компьютер, и проверяем, что он работает без сети.
- **Сервер:** минимальный (Python, FastAPI, SQLite) на личном хостинге. Ручки: `/activate`, `/renew`, `/revoke`. Админ создаёт лицензии из консоли. Только HTTPS. Клиентский HTTP средствами JUCE (на Windows системная библиотека, без curl).
- **Честные границы:** ключ пакета при игре находится в памяти плагина, а декодированные сэмплы лежат в RAM. Решительный человек их достанет отладчиком. Модель угроз: помешать просто скопировать или распаковать сэмплы и поделиться пакетами. В записке так и писать.
- **Вопрос не по коду:** права на библиотеку принадлежат Пачевскому, поэтому формат распространения и срок лицензий согласуем с ним.

## 7. Интерфейс пользователя

- Выбор пресета (список, у каждого значок пакета: установлен, нужен более крупный, нет лицензии).
- Мини-микшер микрофонов: уровень, панорама, Solo/Mute, выбор выхода (запоминается в проекте DAW).
- Клавиши с названиями барабанов и подсветкой звучащих.
- Статус лицензии (до какого числа, кнопка «Обновить»).
- Никакого маппинга, зон и групп.

## 8. Порядок работ

1. Формат: `core/pack`, Monocypher, `samplit-packer`, тесты (round trip, подмена байта ломает чтение, неверный ключ). Можно делать сразу, библиотека не нужна.
2. Модель `Kit/Piece/Hit` и движок: выбор удара, синхронный запуск микрофонов, «Живой», choke, тесты.
3. Скан и разметка по настоящей библиотеке, первые примерочные пакеты (`base`, `cymbals`), пресет.
4. Загрузка пакетов в плагине, фоновая подгрузка, int16 в памяти.
5. Интерфейс: пресеты, микшер микрофонов, служебный режим.
6. Лицензия: токен и проверка в плагине, затем сервер, затем продление.
7. Уровни пакетов (`mid`, `large`) и дополнения.
8. Проверка в Cubase (у кого он есть), Reaper, pluginval; macOS позже.

Пункты 1–2 можно вести параллельно, они независимы. Пункт 3 ждёт список файлов библиотеки.
