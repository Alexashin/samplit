# ТЗ T4: установщик `.splpack` → WAV и импорт файла маппинга

Контрольная точка: 12.11.2026. Только ТЗ, кода нет. Основание: решение 12.11 (`user-stories.md` §«Покупатели»): покупатели получают WAV-библиотеку, `.splpack` нужен только установщику, плагин работает без лицензии. Контракты: `pack-format.md`, `library-structure.md`, `delivery.md`; код: `core/src/Pack.cpp`, `tools/packer/main.cpp` (`extract`), `core/src/License.cpp`, `plugin/LicenseManager.cpp` (`getManifestDir`).

## 1. Пользователи и сценарии

| Кто | Что у него есть | Что нужно |
|---|---|---|
| **Владелец Kontakt-версии Studio600** | Папка `00-Studio600ru-Drum-LIB` (WAV) | Установщик **не нужен**. `Установить.cmd` кладёт манифесты в `%APPDATA%\Samplit\manifests`, плагин читает его папку. Если манифестов нет или версия старая: «Добавить файл маппинга…» в плагине (§6) |
| **Новый клиент** | Скачанные `.splpack` (14 файлов, ≈2,8 ГБ) и файл лицензии | Установщик разворачивает пакеты в WAV-библиотеку (≈7,5 ГБ, 24 бит, без потерь) вместе с манифестами; затем в плагине «Папка звука…» → эта папка |
| **Владелец продукта (мы, Пачевский)** | Ключи пакетов, `issue_license.ps1` | Выпустить токен покупателю; проверить установку из командной строки |

Цифры: в 14 паках 22 980 ссылок на файлы, 21 977 уникальных путей; 172 пути входят в два пакета; у 33 файлов в маппинге задана обрезка `start/end` (при сборке пакета она применена физически). Размер WAV: по замеру RAM float32 9958 МБ → 24 бит ≈ 7,5 ГБ.

## 2. Архитектура: два варианта

**Общее ядро в обоих вариантах:** `core/Installer.{h,cpp}` (без GUI, только `juce_core`, `juce_audio_formats` и уже имеющиеся `Pack`, `Manifest`, `License`): план установки, проверка места, распаковка пакета с журналом, проверка результата, отчёт. Команда `samplit-packer extract` переписывается на это ядро (поведение для нас то же).

| | A. Отдельная утилита «Samplit Установщик» (**рекомендую**) | B. Установка внутри плагина / Standalone |
|---|---|---|
| Где | `tools/installer/`: маленькое GUI-приложение JUCE (`juce_gui_basics` + ядро), плюс `samplit-packer install` для командной строки на том же ядре | Пункт «Установить пакеты…» в меню плагина, код лицензии и расшифровки компилируется в плагин |
| Плюсы | Плагин остаётся без лицензии и криптографии (решение 12.11, `SAMPLIT_LICENSE=OFF`); меньше поверхность атаки в DAW; установщик обновляется отдельно; долгую распаковку (минуты) не делаем внутри Cubase | Один exe; пользователь не ищет вторую программу |
| Минусы | Вторая программа в дистрибутиве и в инструкции | Противоречит решению «плагин без лицензии»; ключи и токен оказываются в процессе DAW; распаковка 7,5 ГБ в фоне плагина конкурирует со стримингом и может быть прервана закрытием проекта; второй вариант сборки плагина |

**Рекомендация: A.** CLI нужен нам для тестов и проверки; покупателю — GUI с тремя полями и одной кнопкой.

## 3. Где лежат манифесты установленной библиотеки (ключевое решение)

Проблема: `Установить.cmd` уже кладёт манифесты с путями **Kontakt-раскладки** (`SNARE/Snare-Ahead/…/0-01.wav`) в `%APPDATA%\Samplit\manifests` под теми же id паков. Распакованная из пакета библиотека имеет другую раскладку (`<packId>/<блок>.wav`, путь в хранимом манифесте не сохраняется) и, у 33 файлов, уже обрезанный звук (`start/end` = 0). Одна папка манифестов на обе раскладки не работает.

Решение: **манифесты живут внутри установленной библиотеки**, `<библиотека>/manifests/<id>.json`, пути в них относительно корня библиотеки. Плагин ищет манифесты в порядке:
1. `<папка звука>/manifests/*.json` (новое; установленная из пакетов библиотека);
2. `%APPDATA%\Samplit\manifests` (Kontakt-раскладка и импорт «Добавить файл маппинга…»);
3. `packs-src` рядом с папкой (как сейчас, для разработки).

Правка `LicenseManager::getManifestDir()` в message thread, audio thread не затрагивается. Состояние проекта не меняется (в нём уже хранится путь папки звука).

Раскладка результата (без изменения формата пакета):

```
<папка установки>\Samplit Studio600\
  manifests\studio600-snare-live.json        пути "studio600-snare-live/123.wav", start=end=0
  studio600-snare-live\123.wav ...           моно, 24 бит, частота из пакета, отсчёты без изменений
  .samplit-install\state.json                журнал установки (служебный)
  install-report.json                        что установлено: паки, версии, файлы, CRC32
```

Альтернатива «восстановить исходные пути Kontakt» требует нового поля `srcPath` в хранимом манифесте и пересборки 14 паков; выигрыш: экономия 172 дублей (<1%) и узнаваемая структура. Не делаем в T4; записано как открытый вопрос.

## 4. Ключи и токены: как не раскрыть

Модель ключа (нужно подтверждение пользователя, по умолчанию K1):
- **K1 (по умолчанию):** покупатель получает токен лицензии в существующем формате (`pack-format.md` §«Токен лицензии», привязка к компьютеру, `issue_license.ps1 -Code …`). Установщик проверяет токен (`verifyTokenFile`) и разворачивает ключи пакетов в памяти. Новой криптографии нет.
- **K2:** токен без привязки к компьютеру («ключ покупки»). Проще покупателю, но это изменение формата токена, от которого отказались ранее; утечка токена + пакетов = чужая установка. Не рекомендую без отдельного решения.
- **K3 (позже):** онлайн-активация через `tools/license_server` (нужен хостинг, только с разрешением).

Правила реализации:
- Ключи пакетов существуют только в памяти процесса установщика; после распаковки пакета стираются (`crypto_wipe`). Не пишутся в журнал, отчёт, лог, сообщения об ошибках, имена файлов.
- Токен только читается; в папку установки и в `%APPDATA%` не копируется. В сообщениях — только статус (`Expired`, `WrongMachine`…) русскими словами, без содержимого токена.
- Ключ из файла (`--key-file`) поддерживается только в CLI для нас и тестов; в GUI такого поля нет.
- В дистрибутив не попадают `~\.samplit-license`, `build\packs-v2\keys`, `license.token` с нашей машины (`make_dist.ps1` копирует только `*.splpack`; добавить проверку: в `dist\` нет файлов `*.key`, `keys\`, `*.token`).
- Результат установки (WAV) не зашифрован: после установки защита пакетов больше не действует. Это принятая цена решения 12.11 (так же, как у Kontakt-версии); шифрование защищает только скачивание.

## 5. Процесс установки, ошибки, повтор после обрыва

1. **Выбор:** папка с `.splpack` (по умолчанию рядом с exe), файл лицензии, папка установки (по умолчанию `Документы\Samplit Studio600`; путь короче 150 символов, иначе предупреждение о длине путей Windows).
2. **План (до записи на диск):** для каждого пакета: заголовок (`magic`, версия 1/2, `packId` = имя файла), разблокировка манифеста ключом из токена, `verifyManifest`, таблица блоков в пределах размера файла (иначе «Пакет недокачан или повреждён: скачайте заново»). Пакет без ключа в токене: «Этого пакета нет в вашей лицензии», остальные ставятся. Место на диске: сумма `frames × 3 + 44` по уникальным блокам + 5%; не хватает — стоп до записи.
3. **Распаковка пакета:** по одному блоку (RAM не растёт): AEAD-тег, FLAC, длина = `frames`, пик = `peak` (если задан); запись `N.wav.part` → проверка заголовка (моно, 24 бит, частота, длина) → переименование в `N.wav`; CRC32 отсчётов считается при записи. Журнал `state.json` обновляется после каждых 200 файлов и в конце пакета (запись через временный файл и переименование).
4. **Манифест пишется последним** (`manifests\<id>.json` через временный файл), только когда все WAV пакета на месте. Плагин никогда не видит манифест со ссылками на отсутствующие файлы.
5. **Отмена / обрыв / сбой питания:** повторный запуск читает журнал; файлы, отмеченные готовыми и совпадающие по размеру, пропускаются; `*.part` удаляются; пакет, у которого изменилась сборка (другой nonce манифеста или размер файла), ставится заново во временную папку `<id>.new` и подменяет старую после успеха. Двойной запуск в одну папку запрещён файлом-замком.
6. **Итог:** `install-report.json`, текст «Готово: N пакетов, M файлов, X ГБ. Откройте Samplit → «Папка звука…» → выберите `…\Samplit Studio600`», кнопка «Скопировать путь». Кнопка «Проверить установку» сверяет файлы с отчётом (размер, при желании CRC32).

Ошибки (русским текстом, без технических деталей в первой строке; подробности в «Показать подробности»): недокачанный/повреждённый пакет, ключ не подходит / лицензия другого компьютера / срок истёк, нет места, нет доступа к папке, путь слишком длинный, файл занят. Каждая ошибка называет пакет и что сделать.

## 6. Импорт файла маппинга в плагине

- Где видно: в строке статуса и на экране первого запуска, когда для выбранной папки звука нет манифестов (сейчас текст «Нет манифестов в …»): кнопка **«Добавить файл маппинга…»**; плюс пункт в меню установки (`ux-plan.md` U3).
- Что выбирают: один или несколько `.json` (манифесты Studio600). Формат «один файл-набор» (`.splmap`) — открытый вопрос, в T4 не делаем.
- Проверки: размер файла ≤ 20 МБ; JSON разбирается `Manifest::fromJson`; `verifyManifest` без ошибок; `id` из белого списка символов (как в `extract`); пути файлов относительные, без `..`, без буквы диска и `\\`. Имя файла назначения берётся из `id`, а не из имени выбранного файла. Если такой манифест уже есть и отличается: спросить «Заменить?».
- Куда: `%APPDATA%\Samplit\manifests` (`config.dataDir/manifests`, не `getManifestDir()`, который теперь может указывать в библиотеку). Затем обновить список паков (`PackCatalog`) и перезагрузить установку тем же путём, что «Обновить список паков». Всё в message thread, копирование с асинхронным `FileChooser`.
- Итог: «Добавлено манифестов: 14. Нашлось файлов: 22 980 из 22 980» (сверка путей с папкой звука; отсутствующие показать списком первых 5).

## 7. Тесты

Ядро (Catch2, `tests/installer_tests.cpp`, тестовые пакеты собираются в тесте `PackWriter` с тестовым ключом и тестовым токеном):
- установка v1 и v2 (голова + хвосты): отсчёты WAV совпадают с исходными побитно; манифест в `manifests\`, пути и `start=end=0`;
- обрыв после N файлов (точка отказа через внедряемый колбэк) → повтор доустанавливает, лишних и `.part` файлов нет, манифест появляется только в конце;
- недокачанный пакет (обрезанный файл) → ошибка до записи, папка установки пуста;
- испорченный байт в блоке → ошибка с номером пакета, манифест не пишется;
- неверный ключ / просроченный / чужой компьютер / пакета нет в токене → понятная ошибка, ключ не встречается в тексте ошибки и в файлах результата (поиск hex ключа по всем файлам папки);
- небезопасный `id` пакета → отказ; нехватка места (внедряемая функция свободного места) → отказ до записи;
- новая сборка пакета поверх старой → замена через `<id>.new`;
- импорт маппинга: корректный, битый JSON, путь с `..`, абсолютный путь, дубликат; `getManifestDir` выбирает папку библиотеки раньше `%APPDATA%`.

Скрытый `[.reallib-install]` (с `SAMPLIT_REAL_LIB` и `build\packs-v2`): установка 14 паков во временную папку, сравнение PCM с исходной библиотекой для всех 22 980 ссылок (33 обрезанных — с обрезанным диапазоном оригинала), загрузка кита в режиме папки без недогрузок. Время и итоговый размер записать в `decisions.md`.
