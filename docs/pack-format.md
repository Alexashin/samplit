# Формат пакета `.splpack` и манифеста (v1)

Общий контракт для потоков: сборщик пакетов (`tools/packer`, `core/src/Pack.cpp`), разметка (`tools/mark_kit.py`), движок (`plugin/Kit*`), лицензия (`core/src/License.cpp`). План и причины решений: `docs/packs-plan.md`.

## Исходный манифест (то, что подаётся сборщику)

JSON, UTF-8. Пути к файлам относительны корню библиотеки, который передаётся сборщику (`--root`).

```json
{
  "format": 1,
  "id": "studio600-base", "version": 1, "tier": "base", "requires": [],
  "title": "Studio600 Drum LIB: базовый",
  "mics": [
    { "id": "kick_in", "name": "Kick In", "role": "close", "out": 1 }
  ],
  "pieces": [
    { "id": "snare", "name": "Малый", "keys": [26], "choke": null,
      "layers": [ { "id": "center_120_127", "artic": "center", "velLo": 120, "velHi": 127 } ],
      "hits": [
        { "id": "snare_26_120", "layer": "center_120_127", "key": 26, "velLo": 120, "velHi": 120,
          "files": {
            "sn_top": { "path": "SNARE/Snare-Ahead/Ahead-LIVE/SN-top/0-01.wav", "gainDb": -3.0, "start": 0, "end": 0 }
          } }
      ] }
  ]
}
```

- `mics[].id` — стабильные идентификаторы микрофонов. `out` — выход по умолчанию 1…16 (моно, выход 0 = Main).
- `pieces[].keys` — клавиши (C3 = 60). Один барабан может занимать несколько клавиш (лево и право, слои на соседних нотах).
- `layers` — слои: окно velocity и артикуляция. Режим «Живой» выбирает слой по velocity, а удар внутри слоя случайно.
- `hits[]` — один удар: клавиша `key`, окно velocity `velLo..velHi` (в библиотеке Studio600 это одно значение), `layer`, файлы по микрофонам. Все файлы удара играются вместе, с одного сэмпла.
- `files[mic]`: `path`, `gainDb` (громкость зоны, 0 по умолчанию), `start` и `end` (обрезка в отсчётах, 0 = без обрезки).
- Поле `peerGroup` у удара (необязательное) — признак группы `-D` из `.nki`, пока не интерпретируется.

## Хранимый манифест (внутри контейнера)

Тот же JSON, но `files[mic]` заменено на `{ "chunk": N, "gainDb": .., "start": .., "end": .., "frames": .., "rate": .., "tailChunk": M }`. `chunk` — номер блока с FLAC всего файла (или только головы, если задан `tailChunk`; способ стриминга хвостов описывает `docs/streaming-design.md`).

## Контейнер

```
magic "SPLP" (4 байта) | formatVersion u32 | packIdLen u16 | packId | manifestLen u32 | nonce(24) | manifest (AEAD) | chunkCount u32
таблица блоков: chunkCount × { offset u64, length u32, nonce(24) }
блоки: FLAC, каждый зашифрован отдельно (XChaCha20-Poly1305, тег 16 байт в конце блока)
```

- Шифрование: Monocypher `crypto_aead_lock/unlock` (XChaCha20-Poly1305). Ключ пакета 32 байта, в контейнере не хранится (его выдаёт токен лицензии). Заголовок (magic, версия, packId) идёт как дополнительные данные AEAD.
- Nonce блока: случайный 24 байта на блок, записан в таблицу блоков.
- Порядок байт little-endian.
- Подпись пакета не нужна: подмена байта ловится тегом AEAD.

## Токен лицензии

JSON `{ "payload": {...}, "sig": "<base64 Ed25519>" }`. Подпись на SHA-512 (Monocypher `crypto_ed25519_*`, совместима с PyNaCl и libsodium). Payload: `licenseId`, `user`, `machine` (хеш отпечатка), `notBefore`, `expires` (Unix, секунды), `packs`: `{ packId: "<ключ пакета, зашифрованный ключом машины, base64>" }`. Подробности в `docs/packs-plan.md`, раздел 6.

## Уточнения по реализации (24.10.2026)

Пакет (`core/src/Pack.cpp`):
- В хранимом манифесте у `HitFile` необязательное поле `peak` (пик в 24-битных единицах, 0 означает файл из нулей). `start` и `end` после сборки равны 0, обрезка применена физически, `path` не хранится.
- Дополнительные данные AEAD блока: заголовок + номер блока (u32). У манифеста только заголовок. `manifestLen` включает тег 16 байт.
- Тихие хвосты при сборке **не обрезаются** (решение 29.10). Поле `tailChunk` читается кодом, но сборщик его не пишет, а загрузчик **отвергает** манифест с `tailChunk >= 0` ошибкой (стриминг сделан для WAV-папки, не для пакетов; `docs/streaming-design.md`).
- Неизвестные поля манифеста (на любом уровне) сохраняются как есть; `requires` в коде называется `requiresPacks`.
- Строковые литералы с русским текстом в ядре пишутся как `"..."_s` (оператор из `Manifest.h`): обычный литерал JUCE читает как Latin-1.

Лицензия (`core/src/License.cpp`):
- Подпись считается по каноническому JSON от `payload`: ключи по возрастанию, без пробелов, не-ASCII без экранирования, числа целые.
- Клиент отправляет серверу сырой отпечаток машины. В токене `machine` = hex BLAKE2b-256(`"samplit-machine-id-v1"` + отпечаток). Ключ обёртки `machineKey` = BLAKE2b-256(`"samplit-machine-key-v1"` + отпечаток) в токен не попадает.
- Обёртка ключа пакета: `base64(nonce24 | шифртекст32 | тег16)`, XChaCha20-Poly1305, AD = `"samplit-packkey-v1:" + packId`.
- Порядок проверок: NoToken, Malformed, BadSignature, ClockRollback, WrongMachine, NotYetValid, Expired.
- В `core/src/LicenseKey.cpp` зашит боевой публичный ключ (`tools/license_server/admin.py init`). Тесты подписывают токены своим тестовым ключом.

## Без потерь (29.10.2026)

По требованию владельца библиотеки звук Studio600 не меняется: `samplit-packer build` **не обрезает хвосты** (флагов обрезки нет; опции сборки: `--root --out --key/--key-file/--gen-key --allow-silent`), в пакете лежит 24-битный FLAC без потерь, плагин держит сэмплы в памяти как float32 (`pack::toFloat24`, значение/8388608, точно для 24 бит), а не int16. Память примерно вдвое больше прежней, размер пакетов растёт. Пакеты пока грузятся в RAM целиком; стримится только режим «Моя библиотека…» (WAV из папки), см. `docs/streaming-design.md`.

`samplit-packer extract <пакет.splpack> --out <новая папка> --key-file <ключ>` расшифровывает блоки по одному и пишет 24-битные моно WAV без изменения отсчётов. В новой папке появляются `<id>.json` и `<id>/<номер блока>.wav`; её можно указать как корень и каталог манифестов для режима локальной библиотеки. Папка назначения должна отсутствовать. При ошибке чтения уже записанная часть остаётся в ней, поэтому повторять распаковку нужно в новую папку.
