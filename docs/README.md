- [project-revision.md](project-revision.md) — **историческая** запись поворота от библиотеки с ИИ-поиском к барабанному инструменту (24.10); её старые «сделать дальше» не использовать как текущий backlog.

## Как разрешать противоречия

1. Для поведения уже реализованной функции — исходный код и тесты (если доступны), затем соответствующий **контракт**.
2. Для текущего состояния и ближайших действий — `current-status.md`, затем новые записи задач в `project-card.md`.
3. Для решения о будущем — явно утверждённое новое решение/ТЗ, затем документы с планами. Исторические записи не переопределяют новые решения.
4. Если код и документы расходятся — **не исправлять факты наугад**. Проверить реализацию и обновить соответствующий документ после подтверждения.

Материалы сверены с кодом 29.10.2026 (ревью проекта): версия 0.2.1, `ctest` в Debug и Release — 140/140, `pluginval` пройден (см. `current-status.md`). Числа и статусы заново сверять при следующем релизе.
