# Редактор партии в плагине (ТЗ первой версии)

Статус: проект 12.11.2026. Основание: проба перетаскивания MIDI из плагина в Cubase прошла (`decisions.md`), решения пользователя в `user-stories.md`. Модель velocity («Удар: плагин / партия», повторяемый выбор) уже в коде.

## Цель

Нарисовать партию прямо в плагине так, чтобы было понятно, что играет, послушать её без Cubase и перетащить на MIDI-дорожку с явными velocity. Парные удары (крещендо малого и альтов) и хуманайз делаются плагином, а не руками в Logical Editor.

## Первая версия

1. **Вкладка «Партия»** (рядом с «Установка / Инструменты / Микшер»). Сетка: строки = включённые места установки (Бочка, Малый, Хэт, тарелки, Ride, томы), столбцы = доли такта (шаг 1/16, длина 1–4 такта, размер 4/4). Клик ставит или убирает удар.
2. **Сила удара словами.** У клетки выбирается удар из групп места (`label` окон: «сильный / средний / тихий / призрачный», группы «Крещендо», «Сбивки»); число velocity ставит плагин. В режиме «Удар: партия» число подбирается под конкретную запись, в режиме «плагин» берётся из середины окна слоя. Клетка показывает слово и число.
3. **Проигрывание в плагине.** Кнопка Play, свой метроном и темп, независимо от транспорта Cubase. Секвенсор в `processBlock` читает готовый снимок партии (неизменяемый объект, смена атомарным указателем, без аллокаций и блокировок), позиция в сэмплах идёт в `setStrikePosition`, поэтому выбор записи повторяем.
4. **Парные удары.** У группы с `pair` (крещендо малого и альтов) переключатель «Играть вместе»: удар одной стороны добавляет парный в строку-партнёра на ту же силу (числа окон совпадают, `peerOk`).
5. **Хуманайз.** Сдвиг по времени (± мс) и по силе (± единиц), зерно хранится в партии: тот же результат при каждом проигрывании и в экспортируемом MIDI.
6. **Перетаскивание в Cubase.** Плашка из пробы экспортирует `.mid` (PPQ 480, темп, клавиши мест, явные velocity, хуманайз запечён). Длина = число тактов.
7. **Хранение.** Партия лежит в состоянии проекта (узел `PATTERN`) и в файле `.json`/`.mid` через кнопки сохранения; пустая по умолчанию.

## Не входит

Импорт MIDI-файла и перенос GM → Studio600, редактирование нот длиннее одной доли, тройки и произвольные размеры, пресеты Logical Editor (отдельной задачей, образец запросить у Пачевского).

## Контракты и риски

- `core/` без JUCE GUI: модель партии (`Pattern`: шаги, места, силы, зерно хуманайза) и генерация событий делаются в `core` или `plugin` без GUI-классов, тестируются отдельно.
- Audio thread: никаких аллокаций; снимок партии заменяется через `std::atomic<std::shared_ptr>`-подобный безопасный обмен либо двойной буфер с hazard-протоколом, как у `Kit`. Ревью обязательно.
- Каждый шаг партии = (место, группа, окно, число velocity); число перепроверяется при смене пака на месте (окна могут измениться): неподходящее число сдвигается к ближайшему окну, ячейка помечается.
- MIDI-файл содержит только ноты и темп; режим «партия/плагин» в файл не входит, подсказка в плагине: для точных записей включить «Удар: партия».

## Порядок работ

1. `Pattern` и генерация событий + тесты (без UI).
2. Секвенсор в `processBlock` + тесты побитового равенства двух рендеров.
3. Вкладка «Партия» (сетка, выбор силы словами), дизайн через `ui-ux-pro-max`.
4. Парные удары, хуманайз.
5. Экспорт `.mid` из партии, состояние проекта, проверка в Cubase 15.
