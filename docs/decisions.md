# Решения и разногласия по документации

Этот документ фиксирует **актуально принятые решения** по состоянию на 29.10.2026 и отмечает более ранние варианты. При изменении решений сначала подтвердить фактическую реализацию и тесты.

| Вопрос | Действующее решение | Ранее / что не переиспользовать |
|---|---|---|
| Основной продукт | Готовый барабанный инструмент Studio600 с пресетами | Менеджер собственной коллекции и сетка 8 пэдов — исторический прототип |
| MIDI | Клавиши, velocity-слои, правило выбора удара `select.pick` | Старое фиксированное соответствие MIDI 36–43 восьми пэдам |
| Выходы | Main стерео + 16 **моно**; 15 микрофонов, запасной выход | Main + 8 стерео / Main + 16 стерео в ранних прототипах |
| Единство удара | Одновременный запуск всех его микрофонов по `.nki` | Поиск соответствий по числовым именам файлов (некорректно) |
| Звук и память | Звук без потерь: float32 (24 бит), без int16 и обрезки хвостов (требование владельца библиотеки, 29.10). Длинные WAV из папки («Моя библиотека…») стримятся с диска (`DiskStreamer`, голова 0,35 с); пакеты `.splpack` v2 тоже: голова в RAM, хвост кусками по 48000 кадров через `PackSource` (12.11) | Решение v1 от 24–28.10 (int16, обрезка тихих хвостов, без стриминга) **отменено** |
| Лицензия | **Отложена (29.10):** по умолчанию выключена (`SAMPLIT_LICENSE=OFF`), звук только из WAV-папки; код токенов и пакетов сохранён для будущего. Служебного токена «на любой компьютер» нет | Сетевое продление и пакеты под токеном не считать включёнными |
| Пользовательский UI | Кит и микс (независимы), схема установки с режимами удара и громкостью барабана, микшер; лицензии в интерфейсе нет | Редактор пэдов/зон — лишь служебный режим Debug |
| Установка (11.11, правки Пачевского) | Пресеты и миксы убираются: фиксированные места Studio600, у места пак своего типа, вкл/выкл, громкость, режимы по **группам** (смысловая разметка `name/role/pair` поверх velocity-чисел Kontakt). ТЗ: `setup-spec.md`. Причина: пресеты оказались слишком сложны для музыканта; группы с ролями и парами дают данные для умного помощника (ВКР) | Пресеты китов и миксов (28.10) — после реализации ТЗ не использовать |
| Данные Studio600 (11.11) | Библиотека разделена на 15 паков: бочка по микрофону (`kick-d12/d6/rode/u87`, все на C0, клавиши 21–24 из `.nki` переносятся полем `outKey`), томы, три малых, хэт, райд, Crash 18/16, China, Splash. Каждый барабан получил `type`, слои собраны в группы с режимами по заметке Пачевского. Удары группы `-D`, проверенные по заметке (хэт F4 и A4), помечены `peerOk` и идут в основной пакет. Причина: разметка должна быть готова до ядра «Установки» | Единый `studio600-core` и `studio600-cymbals` удалены; пресеты в `tools/presets` ссылаются на них и перестанут работать с настоящей библиотекой до задачи B |
| Ядро установки, ревью (11.11) | Реализовано по `setup-spec.md`: `Setup` → `PackCatalog` → `KitSpec` → `loadKit` с кэшем клипов по `sourceKey` (смена пака не перечитывает остальную установку) → публикация; громкость места атомиком в движке; состояние проекта v3 с миграцией v2. Пресеты убраны, потому что для музыканта они сложны; смысловые группы (`role`, `pair`) закладываются как фундамент помощника (ВКР). Найденные при ревью ошибки (причина → исправление): выбор режима группы затирался, когда кит собирался по старому снимку установки → режимы применяются из актуального `Setup` после `setKit`; микшер применялся до публикации кита → порядок изменён (кит, затем микшер); у устаревшей загрузки не вызывался `done` → вызывается с `cancelled`; «Вернуть заводскую» стирала настройки без вопроса → диалог подтверждения | Пресеты и миксы, `PresetLibrary`, `PresetPanel` удалены |
| Выходы (11.11, задача D) | Main st; моно Kick In, Kick Out, Snare Top, Snare Bottom, Hi-Hat, Ride, Room Mid; стерео Toms, Over, Room (микрофоны моно, разводятся стартовой панорамой: Over/Room слева-справа, томы слева направо). Переключатель «Стерео / Мульти-аут», по умолчанию Стерео: человеку без DAW-навыков не нужно ничего включать. Движок уже умел стерео-цель с панорамой, поэтому изменились только раскладка шин, номера `out` в `kit-studio600.json` и стартовая `pan`. Старые проекты Cubase потеряют разводку (0.2.x, пользователей нет) | 15 отдельных моно-выходов и резервный Out 16 |
| Стриминг паков v2, замер (12.11) | Опасение ревью: каждая ячейка декодирует (расшифровка + FLAC) целый кусок ≈1 с, при 40–60 ячейках первый кусок может не успеть за голову 0,35 с. Замер на настоящих паках (Release): `decodeTailChunk` медиана 0,70 мс, p95 1,28 мс, макс. 3,5 мс; 60 ячеек подряд ≈ 80 мс при запасе 350 мс. Аккорды по 8 и 16 ударов (87 и 216 ячеек) 15 с в реальном времени: недогрузок 0, ошибок 0. **Решение: параметры (chunkFrames 48000, одна нить) не менять**, меры (меньший кусок, кэш кусков, несколько нитей) не нужны; добавлены стресс-тесты. RAM голов 1,9 ГБ против 10 ГБ целиком (−80 %) | Меры (a)–(d) из ревью держать в запасе на холодный HDD |
| Стабильный индекс микрофона, В1 (12.11) | Причина: индекс микрофона получался слиянием `mics` манифестов по порядку включённых мест, поэтому от состава установки зависели параметры хоста `micNN_*` (автоматизация молча уезжала на другой микрофон), микшер движка (звучащие хвосты старого кита скачком меняли шину и панораму) и `pushAllParams()` перезаписывал параметры хоста при каждой смене кита. Решение: таблица 15 слотов Studio600 (`kStudio600Mics`), `collectMics` кладёт известные id в свой слот, незнакомые в слоты 15..23, пустые слоты остаются заглушками; микшер и атомики движка индексируются слотом и применяются до `setKit`; параметры `mic_<id>_level/pan` по смыслу; параметры перезаписываются только если микшер изменился (загрузка проекта). Состояние v5 (формат как v4, микшер и так хранился по id). Тесты: индекс не зависит от пакета и выключенных мест, смена кита не меняет параметры и микшер | Автоматизация `micNN_*` в проектах до v5 теряется (пользователей нет); индекс незнакомых id зависит от порядка паков |
| Проверка | C++/Python-тесты, `pluginval`; Cubase — отдельно | Успех старого Reaper с пэдами не означает проверку нынешнего мультимикрофонного роутинга |
| Roadmap | `current-status.md` + рабочие задачи в `project-card.md` | Старые пункты «сделать» из `project-revision.md`/`packs-plan.md` — снимки прошлого |

## Где находится подробное основание

- Технические контракты: `pack-format.md`, `preset-format.md`, `library-structure.md`.
- Измерения памяти и стриминг и режим «Моя библиотека…»: `streaming-design.md`.
- История изменения продукта: `project-revision.md`.
- Очередь задач и этапов: `project-card.md` (статусы снимка сверять с `current-status.md`).

В документации есть записи разных моментов 23–24 октября. Они сохранены как источники проектной истории, но помечены там, где больше **не задают текущую реализацию**.
