Этот документ фиксирует **актуально принятые решения** по состоянию на 29.10.2026 и отмечает более ранние варианты. При изменении решений сначала подтвердить фактическую реализацию и тесты.

Решение: таблица 15 слотов Studio600 (`kStudio600Mics`), `collectMics` кладёт известные id в свой слот, незнакомые в слоты 15..23, пустые слоты остаются заглушками; микшер и атомики движка индексируются слотом и применяются до `setKit`; параметры `mic_<id>_level/pan` по смыслу; параметры перезаписываются только если микшер изменился (загрузка проекта). Состояние v5 (формат как v4, микшер и так хранился по id). Тесты: индекс не зависит от пакета и выключенных мест, смена кита не меняет параметры и микшер | Автоматизация `micNN_*` в проектах до v5 теряется (пользователей нет); индекс незнакомых id зависит от порядка паков |
| Автоматизация микрофонов в audio thread, В2 (12.11) | Причина: уровень и панорама применялись таймером message thread (50 мс по настенным часам): офлайн-экспорт опаздывал и не повторялся, в реальном времени «зиппер» без рампы. Решение: audio thread читает параметры хоста сам в начале блока (mute/solo в атомарных масках), движок идёт к цели линейной рампой на длину блока (состояние по микрофону, не по голосу). Таймер остался только для интерфейса. Заодно: `out=-1` из миграции v≤3 больше не превращается в Main при повторном чтении, `setStateInformation` сразу вызывает `applyMixer`. |
| Проверка | C++/Python-тесты, `pluginval`; Cubase — отдельно | Успех старого Reaper с пэдами не означает проверку нынешнего мультимикрофонного роутинга |
| Roadmap | `current-status.md` + рабочие задачи в `project-card.md` | Старые пункты «сделать» из `project-revision.md`/`packs-plan.md` — снимки прошлого |

## Мелкие замечания ревью (12.11.2026)

- mute и solo лежали в двух атомиках: audio thread мог увидеть половину правки. Теперь одна 64-битная маска (mute в младших 32 битах, solo в старших), одна загрузка на блок.
- Рампа гейна и панорамы равнялась длине блока: при огромном офлайн-блоке нота после размьюта получала атаку на десятки мс. Рампа ограничена `KitEngine::kMaxRampSamples` = 512, `render` режет диапазон на границе рампы.
- Параметр хоста при правке мышью писался без gesture, и Cubase Write/Touch не записывал автоматизацию. Ползунок открывает gesture на время жеста (`beginMicGesture`), остальные правки из UI идут в одиночном gesture; таймер и загрузка проекта пишут без gesture, поэтому обратной связи нет.
- Очередь нот интерфейса при остановленном движке копила залп: в `processBlock` отбрасываются ноты старше `kQueue`; при bypass очередь сбрасывается.
- `getTailLengthSeconds` = длина самого длинного клипа кита (считается в `setKit`, атомик; без кита 30 с). All Sound Off (CC120) и All Notes Off (CC123) гасят все удары за 10 мс (`fadeAll`). `processBlockBypassed` и `releaseResources` сбрасывают голоса (`releaseAll`): замороженные хвосты не доигрываются, старые киты освобождаются.
- Бюджет ожидания диска в офлайн-рендере считался на каждый `render()`, а вызовов на блок несколько: зависший диск давал до 30 с на каждый блок. Теперь бюджет на блок (`beginBlock`), после исчерпания до конца экспорта не ждём (`offlineGaveUp`, сбрасывается в `prepare` и при выходе из офлайна).
- `underruns` увеличивался на каждом куске затухающего голоса: считается один раз на голос (`MicVoice::underrunCounted`).

## 12.11.2026: сила удара вне записанных окон

**Проблема (проверка в Cubase):** при силе 100 (умолчание MIDI-редактора) молчали хэт, тарелки, ride и гост-ноты малого, из клавиатуры плагина играла только часть. **Причина:** в Studio600 на этих клавишах записаны удары только с силой 112–127, а Live-режим при силе вне окон возвращал тишину (как Kontakt), хотя комментарий обещал «ближайший слой». **Решение:** `KitEngine::fitVelocity` сдвигает силу к ближайшему записанному окну (слои «Точно по силе» участвуют, только если других нет; при равенстве берётся более сильный). Ниже самого нижнего окна файл прежний, а уровень снижается пропорционально силе, не больше −18 дБ. Kontakt-режим и «Точно по силе» внутри своих окон не менялись. Смысл силы в Studio600: она выбирает слой записи, а разнообразие даёт режим выбора удара (по кругу, случайно), поэтому партию можно писать с любой силой.

**Побочные правки того же дня:** вкладки больше не образуют радио-группу (подсвечивались две сразу), схема установки перекомпонована без наложений, `setStateInformation` не перезагружает кит, если установка не изменилась.

## 12.11.2026: аудит пути пользователя и новая модель работы с партией

**Основание:** разбор пути «установка → партия → звук → экспорт» ([user-stories.md](user-stories.md)). Найдено: velocity одновременно сила и номер записи (все ноты Cubase идут со 100, звучат непредсказуемо); выбор «случайно/по кругу» делает экспорт не равным прослушиванию; нет drum map; плагин не может менять партию в Cubase; два пути звука (WAV и `.splpack` с лицензией).

**Решения пользователя:**
- Покупатели: владельцы Kontakt-версии и новые клиенты. `.splpack` только для скачивания, установщик разворачивает его в WAV и ставит маппинг; плагин без лицензии, читает WAV. Для неизвестной папки плагин предлагает добавить файл маппинга.
- Схема: левый клик играет, правый открывает настройки места. Над клавиатурой схематическая подсказка зон.
- Переключатель «Удар выбирает: плагин / партия»; по умолчанию плагин: velocity = сила, запись выбирается повторяемо от позиции в песне, опция «живой выбор». Клавиши-последовательности всегда точные.
- Партия пишется и в самом плагине: сначала «Фразы» с перетаскиванием MIDI в Cubase (сначала проба перетаскивания), затем полный редактор. Пресеты Logical Editor (хуманайз, нужная velocity) делаем заготовками; образец запросить у Пачевского.
- Экспорт/импорт установки в файл; drum map Cubase из манифестов.

**Проверено 12.11 (Cubase 15):** пробная плашка перетаскивания MIDI-фразы из плагина работает: файл `.mid` ложится на дорожку, velocity сохраняются как заданы. Значит партию можно создавать в плагине и переносить в Cubase; следующий шаг: «Фразы», затем полноценный редактор партии и заготовки Logical Editor. Клавиши 21–23 (бывшие бочки Kontakt) остаются свободными, алиас на C0 не делаем (решение пользователя).

## 12.11.2026: вкладка «Партия» (P4)

- Строки = включённые места установки в порядке клавиатуры, столбцы = шаги 1/16. Ширина клетки не меньше 36 px: 4 такта в окне 900 px не помещаются, поэтому сетка прокручивается по горизонтали, а подписи мест стоят на месте; курсор проигрывания сам прокручивает сетку.
- В клетке число velocity и слово силы («сильно/средне/тихо»), а не только цвет (правило доступности: информация не только цветом); в узком окне только число, полное описание в подсказке.
- Сила новых ударов выбирается на строку (по умолчанию самый сильный удар основной группы), её выбор не пишется в проект: в проекте хранятся сами удары с точными числами.
- Строка вкладок: четвёртая вкладка не помещалась в 900 px; вкладки и кнопки режимов ужимаются в узком окне вместо переноса кнопок.
- Полоса `LinearBar` для темпа выглядела как пустой квадрат (заливка доли от 30–300); заменена полем с кнопками −/+ и перетаскиванием.

## 12.11.2026: парные удары (P5)

- Логика пар вынесена из окна в `PatternPalette` (без GUI): её можно проверить тестами, а окно только хранит переключатель «вместе» и выбранного партнёра.
- Партнёр по умолчанию: первое подходящее включённое место (для малого Флор том 16, C6), решение пользователя; сменить можно в меню строки. При снятии удара парный снимается, только если на шаге партнёра стоит именно пара, а не удар, поставленный отдельно.
- Скрытый тест на настоящей библиотеке нашёл расхождение: у Альта 12 (`tom_14`) в крещендо нет velocity 70 и 71. Это не ошибка пар, а известные испорченные файлы `TOMS-Pearl-Masters/A2/0-397.wav`, `0-398.wav` (`open-questions.md` §3.1), исключённые через `excludeFiles`. Пара в этом случае берёт ближайшее число (72), а не молчит; в тесте это записано как известное исключение.


## 12.11.2026: файл установки (T2) и экран первого запуска (T5)

- Файл установки = JSON `Setup` плюс свойство `mix` (микрофоны Studio600 по id: уровень, панорама, mute, solo, выход). Старые файлы без `mix` читаются (микшер не трогается); лишние поля игнорируются. Режим «Стерео/Мульти-аут» и партия в файл не входят: это состояние проекта, а не установки.
- Экран первого запуска показывается только без лицензионного режима (с лицензией библиотеку выбирать не нужно), без выбранной папки и без кита; панель сама скрывается, когда кит появился. Снимок делается в сборке с лицензией, где панель скрыта, поэтому вид проверен временным принудительным показом.

## 12.11.2026 ночью: план упрощения окна и ТЗ установщика

- UX: из трёх вариантов (только слова; три вкладки с раскрытием по шагам; один «простой» экран + режим «Профи») выбран средний. Причина: главная путаница в двух вкладках про одни и те же барабаны и в глобальных режимах на виду; второй интерфейс («Профи») удвоил бы поддержку. Состояние проекта не меняется, всё в окне. Найдено при разборе: распакованная из пакета библиотека не совпадает по раскладке с Kontakt-папкой, а у 33 файлов обрезка уже применена в пакете; общая папка манифестов в `%APPDATA%` дала бы конфликт id и двойную обрезку. Поэтому манифесты установленной библиотеки лежат в ней самой (`<папка>/manifests`), плагин ищет их там первыми. Подробно: `installer-spec.md`.
